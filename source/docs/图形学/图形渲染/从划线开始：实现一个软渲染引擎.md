# 从画线开始：实现一个软渲染引擎

&emsp;&emsp;现如今大部分GPU都支持GL、Vulkan等渲染API，这些API将顶点变换、光栅化、纹理采样、深度测试等复杂流程封装成简洁的调用接口，开发者只需传入几何数据和着色器代码，就能高效地渲染出逼真的三维场景。然而，正是这种高度抽象让我们难以窥见图形渲染的内部机制——像素是如何被逐个点亮的？三角形如何被填充？深度缓冲又是怎样避免物体穿插的？要真正理解这些问题，最好的方式莫过于亲手实现一个不依赖任何图形API的软渲染引擎，从最基础的像素操作开始，逐步构建完整的渲染管线。

&emsp;&emsp;本文将基于 **SoftGameEngine**（一个纯 CPU 实现的 C++20 软渲染引擎），从画线开始，逐步讲解如何构建一个功能完整的软件渲染器。引擎使用 SDL2 仅负责窗口创建与像素上屏，所有图形管线（光栅化、光照、阴影、PBR、光线追踪）均在 CPU 上完成。

## 1 几何图形

### 1.1 从划线开始

&emsp;&emsp;划线是软渲染中最基础的操作。在光栅化屏幕上，直线并不是连续的数学对象，而是由离散的像素点近似表示。因此核心问题是：**给定两个屏幕坐标点，如何确定哪些像素应该被点亮？**

#### 1.1.1 Bresenham 画线算法

&emsp;&emsp;最经典的解决方案是 Bresenham 画线算法。其核心思想是：在每一步中，通过一个整数误差项 `err` 来决定下一个像素应该沿主轴移动一步，还是沿次轴移动一步。

&emsp;&emsp;算法流程如下：

1. **计算增量**：设起点 $(x_0, y_0)$，终点 $(x_1, y_1)$，令 $dx = |x_1 - x_0|$，$dy = -|y_1 - y_0|$（负号表示次轴方向为递减），并确定每步的符号 $sx = \text{sign}(x_1 - x_0)$，$sy = \text{sign}(y_1 - y_0)$。

2. **初始化误差**：$err = dx + dy$。

3. **迭代绘制**：每一步绘制当前像素 $(x_0, y_0)$，然后计算 $e_2 = 2 \cdot err$：
   - 若 $e_2 \geq dy$，说明误差已超过次轴阈值，沿主轴移动：$err \mathrel{+}= dy$，$x_0 \mathrel{+}= sx$；
   - 若 $e_2 \leq dx$，说明误差已低于主轴阈值，沿次轴移动：$err \mathrel{+}= dx$，$y_0 \mathrel{+}= sy$。

4. **终止条件**：当 $(x_0, y_0) = (x_1, y_1)$ 时结束。

&emsp;&emsp;该算法的优势在于**全程仅使用整数加法和位移运算**，无需浮点乘除，非常适合 CPU 逐像素操作。

#### 1.1.2 代码实现

&emsp;&emsp;在 SoftGameEngine 中，画线由 `Rasterizer::drawLine` 实现：

```cpp
void Rasterizer::drawLine(const ScreenVertex &a, const ScreenVertex &b) {
    int x0 = static_cast<int>(std::lround(a.x)), y0 = static_cast<int>(std::lround(a.y));
    int x1 = static_cast<int>(std::lround(b.x)), y1 = static_cast<int>(std::lround(b.y));
    int dx = std::abs(x1 - x0), sx = x0 < x1 ? 1 : -1;
    int dy = -std::abs(y1 - y0), sy = y0 < y1 ? 1 : -1;
    int err = dx + dy;
    while (true) {
        plot(x0, y0, a.color);
        if (x0 == x1 && y0 == y1) break;
        auto e2 = 2 * err;
        if (e2 >= dy) { err += dy; x0 += sx; }
        if (e2 <= dx) { err += dx; y0 += sy; }
    }
}
```

&emsp;&emsp;其中 `plot` 函数负责将颜色写入帧缓冲：

```cpp
void Rasterizer::plot(int x, int y, const Color32 &c) {
    if (x < 0 || y < 0 || x >= static_cast<int>(m_fb.width())
        || y >= static_cast<int>(m_fb.height())) return;  // 边界裁剪
    m_fb.colorData()[static_cast<std::size_t>(y) * m_fb.width()
                     + static_cast<std::size_t>(x)] = PackBGRA(c);  // 一维数组存储二维像素
}
```

&emsp;&emsp;帧缓冲采用**行优先一维数组**存储，像素 $(x, y)$ 的索引为 $y \cdot width + x$，颜色格式为 `PackBGRA` 打包的 `0xAARRGGBB` 整数（对应小端内存字节序的 BGRA，与 SDL2 窗口 ARGB8888 上屏格式一致）。

#### 1.1.3 坐标系统

&emsp;&emsp;SoftGameEngine 采用**屏幕坐标系**：原点在左上角，$x$ 轴向右，$y$ 轴向下。渲染分辨率为 800×600（由 `g_renderW` 和 `g_renderH` 定义）。所有顶点在经过模型-视图-投影变换和透视除法后，被映射到该坐标系中进行光栅化。

### 1.2 三角形光栅化

&emsp;&emsp;三角形是 GPU 渲染的基本图元，所有复杂几何体最终都会被分解为三角形进行渲染。三角形光栅化的核心问题是：**如何确定哪些像素位于三角形内部？** 以及 **如何在三角形内部正确插值顶点属性（颜色、纹理坐标、法线等）？**

#### 1.2.1 重心坐标法

&emsp;&emsp;重心坐标（Barycentric Coordinates）是判断像素是否在三角形内部的标准方法。对于三角形 $(v_0, v_1, v_2)$，任意点 $P$ 的重心坐标 $(w_0, w_1, w_2)$ 满足：

$$P = w_0 \cdot v_0 + w_1 \cdot v_1 + w_2 \cdot v_2$$

&emsp;&emsp;其中 $w_0 + w_1 + w_2 = 1$。若 $w_0, w_1, w_2 \geq 0$，则点 $P$ 在三角形内部；若有任一分量为负，则点在三角形外部。

&emsp;&emsp;重心坐标的几何意义是：$w_0$ 等于三角形 $Pv_1v_2$ 面积与 $v_0v_1v_2$ 面积之比。因此，重心坐标可以用于**线性插值**三角形内部的任意顶点属性：

$$\text{attribute}(P) = w_0 \cdot a_0 + w_1 \cdot a_1 + w_2 \cdot a_2$$

&emsp;&emsp;其中 $a_0, a_1, a_2$ 是三个顶点的属性值（颜色、纹理坐标、法线等）。

#### 1.2.2 边函数（Edge Function）

&emsp;&emsp;重心坐标可通过**边函数**（Edge Function）高效计算。边函数定义为：

$$E_{AB}(P) = (B_x - A_x)(P_y - A_y) - (B_y - A_y)(P_x - A_x)$$

&emsp;&emsp;该函数返回有向面积（的两倍），正值表示 $P$ 在 $AB$ 左侧，负值表示在右侧，零表示在直线上。

&emsp;&emsp;三角形面积为：

$$\text{Area} = E_{v_0 v_1}(v_2) = (v_1.x - v_0.x)(v_2.y - v_0.y) - (v_1.y - v_0.y)(v_2.x - v_0.x)$$

&emsp;&emsp;重心坐标为：

$$w_0 = \frac{E_{v_1 v_2}(P)}{\text{Area}}, \quad w_1 = \frac{E_{v_2 v_0}(P)}{\text{Area}}, \quad w_2 = \frac{E_{v_0 v_1}(P)}{\text{Area}}$$

&emsp;&emsp;边函数的一个重要性质是**增量计算**：当像素从 $(x, y)$ 移动到 $(x+1, y)$ 时，边函数的变化量仅取决于三角形的边方向，与像素位置无关。这使得光栅化可以高效地逐行扫描。

#### 1.2.3 Top-Left 规则

&emsp;&emsp;为避免相邻三角形的边界像素被重复绘制或遗漏，需要定义**填充规则**。SoftGameEngine 采用 **Top-Left 规则**：

- **Top 边**：水平边中 $y$ 值较小的一条（即上方的边）
- **Left 边**：从上到下扫描时，左侧的边（即 $y$ 增加方向上，$x$ 减小的边）

&emsp;&emsp;位于 Top 边或 Left 边上的像素被视为"内部"，位于 Bottom 边或 Right 边上的像素被视为"外部"。这确保了相邻三角形的边界像素不会被重复绘制，也不会被遗漏。

```cpp
bool IsTopLeftEdge(double ax, double ay, double bx, double by) {
    if (ay == by) return ax < bx;  // 水平边：从左到右为 Top
    return by > ay;                 // 非水平边：向下为 Left
}

// 判断像素是否在三角形内部
auto inside = [&](double w, bool topLeft) {
    return w > eps || (topLeft && w >= -eps);
};
```

#### 1.2.4 扫描线优化

&emsp;&emsp;朴素的重心坐标法需要遍历三角形包围盒内的所有像素。通过**扫描线算法**可以进一步优化：逐行扫描，利用边函数的增量性质，每行只需计算一次起始 $x$，然后沿 $x$ 方向增量更新。

&emsp;&emsp;SoftGameEngine 的实现遍历包围盒（未采用增量更新），但包含以下优化：

1. **包围盒裁剪**：将遍历范围限制在屏幕和 tile 裁剪区域内
2. **逐像素独立计算**：当前实现未做增量更新——边函数在每个像素重新计算（`w0/w1/w2` 各自调用一次 `EdgeFunction`），教学清晰优先，增量更新留给读者作为练习
3. **提前拒绝**：一旦发现任一重心坐标不满足内部条件（违反 Top-Left 规则），立即 `continue` 跳过该像素；此外当透视校正分母 $iw = w_0/v_0.w + w_1/v_1.w + w_2/v_2.w \le 0$ 时也直接跳过

&emsp;&emsp;真正的增量式边函数优化（每行起点一次计算、沿 $x$ 步进只做加法）可作为后续性能优化方向；引擎另以 `TileRenderer`（tile 并行，配合 `Rasterizer` 的 `ScreenRect` 裁剪区）提升多核吞吐，与增量式边函数优化互补。

#### 1.2.5 顶点属性插值

&emsp;&emsp;在三角形内部，所有顶点属性（颜色、纹理坐标、法线、深度等）都通过重心坐标插值得到：

```cpp
// 顶点色插值（仿射插值，逐通道 clamp 加权）

uint8_t g = clamp((int)v0.color.g * w0 + (int)v1.color.g * w1 + (int)v2.color.g * w2);
uint8_t b = clamp((int)v0.color.b * w0 + (int)v1.color.b * w1 + (int)v2.color.b * w2);

// 深度插值（透视校正，见 1.3.1 节）
float z = (w0 * v0.z / v0.w + w1 * v1.z / v1.w + w2 * v2.z / v2.w) / iw;

// 纹理坐标插值（透视校正，见 1.3.1 节）
```

#### 1.2.6 代码实现

&emsp;&emsp;`Rasterizer::drawTriangleSolid` 实现了实心三角形填充：

```cpp
void Rasterizer::drawTriangleSolid(const ScreenVertex &v0, const ScreenVertex &v1,
                                   const ScreenVertex &v2) {
    // 1. 计算三角形面积（有向）
    double area = EdgeFunction(v0.x, v0.y, v1.x, v1.y, v2.x, v2.y);
    if (area == 0) return;                    // 退化三角形
    if (cullBackface && area < 0) return;     // 背面剔除

    double invArea = 1.0 / area;

    // 2. 计算包围盒（裁剪到屏幕范围）
    int x0 = std::max(0, (int)floor(minX));
    int y0 = std::max(0, (int)floor(minY));
    int x1 = std::min((int)m_fb.width() - 1, (int)ceil(maxX));
    int y1 = std::min((int)m_fb.height() - 1, (int)ceil(maxY));

    // 3. 预计算 Top-Left 标记
    bool tl0 = IsTopLeftEdge(v1.x, v1.y, v2.x, v2.y);
    bool tl1 = IsTopLeftEdge(v2.x, v2.y, v0.x, v0.y);
    bool tl2 = IsTopLeftEdge(v0.x, v0.y, v1.x, v1.y);

    // 4. 遍历包围盒内每个像素
    for (int y = y0; y <= y1; y++) {
        for (int x = x0; x <= x1; x++) {
            double px = x + 0.5, py = y + 0.5;  // 像素中心

            // 5. 计算重心坐标
            double w0 = EdgeFunction(v1.x, v1.y, v2.x, v2.y, px, py) * invArea;
            double w1 = EdgeFunction(v2.x, v2.y, v0.x, v0.y, px, py) * invArea;
            double w2 = EdgeFunction(v0.x, v0.y, v1.x, v1.y, px, py) * invArea;

            // 6. Top-Left 规则判断
            if (!inside(w0, tl0) || !inside(w1, tl1) || !inside(w2, tl2)) continue;

            // 7. 插值顶点属性，带深度测试写入帧缓冲（blendPixel 内部做 Z-Buffer 判定）
            Color32 c = interpolateColor(v0, v1, v2, w0, w1, w2);
            uint32_t packed = PackBGRA(c);
            double zNdc = (w0 * v0.z / v0.w + w1 * v1.z / v1.w + w2 * v2.z / v2.w)
                          / (w0 / v0.w + w1 / v1.w + w2 / v2.w);
            m_fb.blendPixel(x, y, packed, static_cast<float>(zNdc));
        }
    }
}
```

### 1.3 纹理映射

&emsp;&emsp;纹理映射是将 2D 图像"贴"到 3D 表面的技术。每个三角形顶点携带纹理坐标 $(u, v)$，光栅化时通过重心坐标插值得到每个像素的纹理坐标，再从纹理图像中采样颜色。纹理坐标范围通常为 $[0, 1]$。需要注意：引擎采用**左上角原点**约定，$(0, 0)$ 对应图像首行（顶部）像素，$(1, 1)$ 对应末行（底部），与 OpenGL 教科书"左下角原点"的约定不同。

#### 1.3.1 透视校正插值

&emsp;&emsp;直接对纹理坐标进行仿射插值会导致**透视失真**。原因在于：透视投影后，近处三角形占据更多屏幕像素，但纹理坐标的变化并不均匀。如果直接用屏幕空间的重心坐标插值，纹理会出现"扭曲"。

&emsp;&emsp;正确做法是使用**透视校正插值**。核心思想是：在观察空间中，属性是线性变化的。因此先对 $1/w$ 做重心插值作为分母，再对 $u/w$ 做插值后归一化：

$$\text{iw} = \lambda_0 \cdot \frac{1}{w_0} + \lambda_1 \cdot \frac{1}{w_1} + \lambda_2 \cdot \frac{1}{w_2}, \qquad
u = \frac{\lambda_0 \cdot \frac{u_0}{w_0} + \lambda_1 \cdot \frac{u_1}{w_1} + \lambda_2 \cdot \frac{u_2}{w_2}}{\text{iw}}$$

&emsp;&emsp;其中 $\lambda_0,\lambda_1,\lambda_2$ 是三个顶点的**重心坐标**（$\lambda_0+\lambda_1+\lambda_2=1$），$w_0,w_1,w_2$ 是三个顶点裁剪空间的 $w$ 分量（$w_{clip} = -z_{view}$，即观察空间深度的相反数）。同理，纹理坐标 $v$、深度 $z$、法线等属性都需要透视校正。

```cpp
// 透视校正插值
double iw = w0 / v0.w + w1 / v1.w + w2 / v2.w;  // 1/w 的插值
double u = (w0 * v0.u / v0.w + w1 * v1.u / v1.w + w2 * v2.u / v2.w) / iw;
double v = (w0 * v0.v / v0.w + w1 * v1.v / v1.w + w2 * v2.v / v2.w) / iw;
double z = (w0 * v0.z / v0.w + w1 * v1.z / v1.w + w2 * v2.z / v2.w) / iw;
```

#### 1.3.2 纹理过滤

&emsp;&emsp;当纹理像素（texel）与屏幕像素不一一对应时，需要进行纹理过滤。如果一个屏幕像素覆盖多个 texel（物体远离相机时纹理被**缩小** minification），或者多个屏幕像素对应同一个 texel（物体靠近相机时纹理被**放大** magnification），直接取最近的 texel 会产生锯齿或闪烁。

&emsp;&emsp;SoftGameEngine 支持三种纹理过滤方式：

| 过滤方式 | 原理 | 特点 | 性能 |
|---------|------|------|------|
| **最近邻** | 取最近的 texel | 速度快，有锯齿 | 最快 |
| **双线性** | 4 个 texel 加权平均 | 平滑，性能适中 | 中等 |
| **三线性** | 两层 mipmap 双线性插值 | 消除远近过渡闪烁 | 较慢 |

**最近邻采样**：

```cpp
uint32_t NearestSample(int tx, int ty) {
    tx = ((tx % size) + size) % size;   // 真模，正确处理负数
    ty = ((ty % size) + size) % size;
    return pixels[ty * width + tx];
}
```

**双线性插值**：

```cpp
uint32_t BilinearSample(double u, double v) {
    // 半像素偏移：将 texel 中心对齐到整数网格，使 (0,0) 像素中心
    // (u=0,v=0) 采样到第一个 texel 中心，避免整数坐标落在格线上
    double fx = u * width - 0.5;
    double fy = v * height - 0.5;

    // 锚点取 floor 后的整数 texel，即当前采样点左下方的 texel
    // （fx/fy 为负时落在 (0,0) 上方/左侧，由环绕模式决定取哪个 texel）
    int x0 = (int)floor(fx), y0 = (int)floor(fy);

    // 插值权重：采样点与锚点的分数距离
    double ax = fx - x0, ay = fy - y0;

    // 四个 texel 的颜色（越界由环绕模式决定）
    uint32_t c00 = get(x0, y0), c10 = get(x0 + 1, y0);
    uint32_t c01 = get(x0, y0 + 1), c11 = get(x0 + 1, y0 + 1);

    // 双线性插值（BlendChannel 按通道加权）
    return BlendChannel(c00, c10, c01, c11, ax, ay);
}
```

&emsp;&emsp;纹理环绕模式决定了超出 $[0, 1]$ 范围的坐标如何处理：

| 环绕模式 | 行为 | 数学表达 |
|---------|------|---------|
| **Repeat** | 重复纹理 | $u = u \mod 1$ |
| **Clamp** | 钳制到边缘像素 | $u = \text{clamp}(u, 0, 1)$ |

#### 1.3.3 Mipmap

&emsp;&emsp;Mipmap 是预计算的纹理金字塔，每层分辨率减半。当纹理被缩小时（物体远离相机），使用较高层级的 mipmap 可以避免闪烁和走样。

**Mipmap 生成**：

&emsp;&emsp;每一层 mipmap 是下一层的 2×2 像素平均（对于非 2 的幂尺寸，边缘会重复取边界 texel 参与平均）：

$$\text{Level}[k](x, y) = \frac{1}{4} \left( \text{Level}[k-1](2x, 2y) + \text{Level}[k-1](2x+1, 2y) + \text{Level}[k-1](2x, 2y+1) + \text{Level}[k-1](2x+1, 2y+1) \right)$$

&emsp;&emsp;例如，一张 256×256 的纹理，mipmap 链为：

| Level | 分辨率 | 大小 |
|-------|--------|------|
| 0 | 256×256 | 256 KB |
| 1 | 128×128 | 64 KB |
| 2 | 64×64 | 16 KB |
| 3 | 32×32 | 4 KB |
| ... | ... | ... |

**LOD 计算**：

&emsp;&emsp;通过计算同一扫描线上相邻像素在纹理空间的距离差，估算 LOD（Level of Detail）：

$$\text{lod} = \log_2 \left( \max\left(\left|du/dx\right| \cdot W, \left|dv/dx\right| \cdot H\right) \right)$$

&emsp;&emsp;其中 $W$、$H$ 为纹理宽高（将 UV 差换算为 texel 距离）。当 lod 为整数时，直接选择对应层级；为小数时，在两层之间插值（三线性过滤）。

#### 1.3.4 三线性过滤

&emsp;&emsp;三线性过滤在两个 mipmap 层级之间进行双线性插值，消除层级切换时的突变：

```cpp
uint32_t sampleTrilinear(double u, double v, float lod, TextureWrap wrap) {
    // lod 钳制到有效层级范围
    float clamped = std::clamp(lod, 0.0f, (float)(mips.size() - 1));
    int lod0 = (int)clamped;
    int lod1 = std::min((int)mips.size() - 1, lod0 + 1);
    float t = clamped - lod0;

    // 在两层分别双线性采样
    uint32_t c0 = BilinearSampleLod(u, v, lod0, wrap);
    uint32_t c1 = BilinearSampleLod(u, v, lod1, wrap);

    // 在两层之间插值
    return mix(c0, c1, t);
}
```

#### 1.3.5 完整纹理三角形

&emsp;&emsp;将纹理映射集成到三角形光栅化中，实现带纹理的三角形绘制：

```cpp
void Rasterizer::drawTriangleTextured(const ScreenVertex &v0, const ScreenVertex &v1,

    }
}
```

## 2 渲染管线

### 2.1 从顶点到像素：完整管线

&emsp;&emsp;渲染管线是将 3D 几何数据转换为 2D 屏幕图像的一系列固定步骤。理解渲染管线是理解图形学的基石。SoftGameEngine 的管线流程如下：

```
模型空间顶点 → [Model变换] → 世界空间 → [View变换] → 观察空间
    → [Projection变换] → 裁剪空间 → [透视除法] → NDC空间
    → [视口映射] → 屏幕空间 → [光栅化] → 像素
```

&emsp;&emsp;每个步骤都有其数学原理和实际意义：

| 步骤 | 输入空间 | 输出空间 | 核心操作 |
|------|---------|---------|---------|
| Model 变换 | 模型空间 | 世界空间 | 平移、旋转、缩放 |
| View 变换 | 世界空间 | 观察空间 | 相机对齐 |
| Projection | 观察空间 | 裁剪空间 | 透视/正交投影 |
| 透视除法 | 裁剪空间 | NDC 空间 | 除以 $w$ |
| 视口映射 | NDC 空间 | 屏幕空间 | 坐标范围映射 |
| 光栅化 | 屏幕空间 | 像素 | 三角形填充 |

#### 2.1.1 Model 变换

&emsp;&emsp;Model 变换将物体从模型空间变换到世界空间。模型空间是以物体自身为原点的坐标系，世界空间是整个场景的统一坐标系。

&emsp;&emsp;Model 变换通常分解为**缩放→旋转→平移**的组合：

$$M = T \cdot R_y \cdot R_x \cdot S$$

&emsp;&emsp;注意矩阵乘法的顺序：先缩放，再旋转，最后平移（从右向左应用）。

```cpp
// 构建 Model 矩阵
auto model = SGE::Math::translation(tx, ty, tz)    // 平移到世界位置
           * SGE::Math::rotationY(ry)               // 绕 Y 轴旋转
           * SGE::Math::rotationX(rx)               // 绕 X 轴旋转
           * SGE::Math::scale(sx, sy, sz);          // 缩放
```

&emsp;&emsp;**法线变换**需要特殊处理。法线不能直接用 Model 矩阵变换，否则在非均匀缩放时会出现错误。正确做法是使用**法线矩阵**（Model 矩阵左上 3×3 的逆转置）：

$$N_{world} = (M^{-1})^T \cdot N_{local}$$

```cpp
// 法线矩阵：逆转置
auto normalMat = SGE::Math::normalMatrix(model);
// 等价于: transpose(inverse(model.upper3x3()))
```

#### 2.1.2 View 变换

&emsp;&emsp;View 变换将世界空间变换到观察空间（以相机为原点，看向 $-z$ 方向）。相机通过 `lookAt` 矩阵定义，包含三个关键向量：

- **位置**（eye）：相机在世界空间的位置
- **目标**（center）：相机看向的点
- **上方向**（up）：通常为 $(0, 1, 0)$

&emsp;&emsp;LookAt 矩阵的构建：

$$\text{forward} = \text{normalize}(center - eye)$$
$$\text{right} = \text{normalize}(\text{forward} \times up)$$
$$\text{up} = \text{right} \times \text{forward}$$

$$V = \begin{bmatrix}
right.x & right.y & right.z & -right \cdot eye \\
up.x & up.y & up.z & -up \cdot eye \\
-forward.x & -forward.y & -forward.z & forward \cdot eye \\
0 & 0 & 0 & 1
\end{bmatrix}$$

```cpp
auto view = camera.viewMatrix();
// 等价于:
auto view = SGE::Math::lookAt(eye, center, up);
```

&emsp;&emsp;SoftGameEngine 的相机参数包括位置 `position`、偏航角 `yaw`、俯仰角 `pitch`（均使用**弧度**），通过 `forward()` 计算观察方向：

```cpp
Vector3D forward() const {
    return {
        std::sin(yaw) * std::cos(pitch),   // x 分量
        std::sin(pitch),                    // y 分量
        std::cos(yaw) * std::cos(pitch)    // z 分量
    };
}
```

#### 2.1.3 Projection 变换

&emsp;&emsp;透视投影将观察空间变换到裁剪空间，产生**近大远小**的效果。投影矩阵将视锥体（frustum）变换为一个轴对齐的立方体（$[-1, 1]^3$），便于后续裁剪。

&emsp;&emsp;透视投影矩阵：

$$P = \begin{bmatrix}
\frac{1}{\tan(\frac{fovY}{2}) \cdot aspect} & 0 & 0 & 0 \\
0 & \frac{1}{\tan(\frac{fovY}{2})} & 0 & 0 \\
0 & 0 & \frac{far + near}{near - far} & \frac{2 \cdot far \cdot near}{near - far} \\
0 & 0 & -1 & 0
\end{bmatrix}$$

&emsp;&emsp;其中：
- $fovY$：垂直视场角（通常 45°~90°）
- $aspect$：宽高比（width/height）
- $near$、$far$：近裁剪面和远裁剪面距离

&emsp;&emsp;矩阵最后一行为 $(0, 0, -1, 0)$，这使得 $w_{clip} = -z_{view}$，即裁剪空间的 $w$ 分量等于观察空间的 $z$ 值（取反）。这正是透视除法产生近大远小效果的关键。

```cpp
auto proj = SGE::Math::perspective(fovY, aspect, near, far);
```

&emsp;&emsp;**正交投影**不产生透视效果，常用于 2D 渲染和阴影贴图生成：

$$P_{ortho} = \begin{bmatrix}
\frac{2}{r-l} & 0 & 0 & -\frac{r+l}{r-l} \\
0 & \frac{2}{t-b} & 0 & -\frac{t+b}{t-b} \\
0 & 0 & \frac{2}{n-f} & -\frac{n+f}{n-f} \\
0 & 0 & 0 & 1
\end{bmatrix}$$

#### 2.1.4 透视除法与视口映射

&emsp;&emsp;裁剪空间坐标除以 $w$ 得到 NDC（Normalized Device Coordinates），范围 $[-1, 1]$。然后映射到屏幕空间：

$$x_{screen} = (x_{ndc} \cdot 0.5 + 0.5) \cdot width$$
$$y_{screen} = (1 - (y_{ndc} \cdot 0.5 + 0.5)) \cdot height$$

&emsp;&emsp;注意 $y$ 轴翻转：NDC 向上为正，屏幕坐标向下为正。

&emsp;&emsp;透视除法后，$w$ 分量被保留下来，用于后续的**透视校正插值**。

&emsp;&emsp;完整管线（模型变换→视图→投影→裁剪→光栅化）的输出示例（`SimpleGeometry` 场景：四角彩色房体 + 白顶尖）：

### 2.2 视锥裁剪

&emsp;&emsp;位于视锥体外的三角形必须被裁剪，否则会导致光栅化错误（例如 $w$ 为负导致透视除法异常）。SoftGameEngine 实现了**六平面 Sutherland-Hodgman 裁剪**：

#### 2.2.1 视锥体定义

&emsp;&emsp;视锥体由六个平面定义：近、远、左、右、上、下。每个平面方程为 $ax + by + cz + d = 0$，法线指向视锥体内侧。

#### 2.2.2 Sutherland-Hodgman 算法

&emsp;&emsp;算法对多边形逐平面裁剪。对于每个平面：

1. 遍历多边形的每条边
2. 如果边的两个端点都在平面内侧，保留终点
3. 如果边从外侧进入内侧，计算交点并保留交点和终点
4. 如果边从内侧到外侧，仅保留交点

&emsp;&emsp;裁剪时需要**精确插值所有顶点属性**（位置、纹理坐标、法线、$w$ 分量等），确保裁剪后的三角形属性正确。（注：颜色在裁剪时取源顶点颜色、不参与插值，实际实现见 `Pipeline::LerpClip`。）

```cpp
// 实际 API：输入裸数组，输出已裁剪好的三角形列表（fan 三角化）
std::vector<ScreenTriangle> Pipeline::clipTriangle(const ScreenVertex (&tri)[3]);

// 内部：对三角形每个顶点做六平面 Sutherland-Hodgman 裁剪
// ClipPolygon 插值 x/y/z/w/u/v/nx/ny/nz/wx/wy/wz，颜色取源顶点
```

#### 2.2.3 裁剪的必要性

&emsp;&emsp;不进行裁剪会导致：
- **$w$ 为负**：透视除法产生错误坐标
- **纹理坐标溢出**：采样纹理边界外的内存
- **光栅化越界**：遍历范围超出屏幕

### 2.3 背面剔除

&emsp;&emsp;对于封闭物体，背面三角形永远不可见，可以提前剔除以节省光栅化开销。SoftGameEngine 通过屏幕空间有向面积判断背面：

```cpp
bool Pipeline::isBackFacing(const ScreenVertex &a, const ScreenVertex &b,
                           const ScreenVertex &c) {
    double area = (b.x - a.x) * (c.y - a.y) - (b.y - a.y) * (c.x - a.x);
    return area < 0;  // 负面积为背面（取决于顶点绕序和y轴方向）
}
```

&emsp;&emsp;背面剔除的前提是物体是**封闭的**（水密的），且三角形绕序一致。需要说明的是，本引擎视口映射时进行了 $y$ 翻转（y-down 屏幕空间），因此正面三角形在屏幕空间的有向面积为**正**（相当于 y-down 坐标系中的顺时针绕序），管线 `projectObject` 始终对每个三角形执行 `isBackFacing` 剔除。对于开放曲面（如地面），靠正面绕序保留，无需关闭剔除；光栅化阶段的 `Rasterizer::cullBackface` 开关默认关闭，只影响 `drawTriangle*` 系列函数。

### 2.4 深度缓冲

&emsp;&emsp;深度缓冲（Z-Buffer）解决物体遮挡问题。每个像素存储最近的深度值，新像素只有在更近时才写入：

```cpp
void FrameBuffer::setPixel(size_t x, size_t y, uint32_t bgra, float depth) {
    if (x >= m_width || y >= m_height) return;
    if (!std::isfinite(depth)) return;

    auto idx = y * m_width + x;
    if (depth >= m_depth[idx]) return;  // 更远，跳过
    m_depth[idx] = depth;
    m_color[idx] = bgra;
}
```

&emsp;&emsp;深度缓冲的存储格式与用途有关，存在两套约定：
- **阴影深度贴图**（`drawTriangleDepth` 写入）：从 NDC 空间 $[-1, 1]$ 映射到 $[0, 1]$（$z_{01} = z_{ndc} \cdot 0.5 + 0.5$），与主 pass 比较时的归一化尺度一致
- **主渲染 pass**（`drawTriangleSolid`/`drawTriangleTextured` 经 `blendPixel` 写入）：直接传入 $z_{ndc}$（未映射），因为深度测试只需比较相对远近，单调性保持一致即可

$$z_{01} = z_{ndc} \cdot 0.5 + 0.5$$

&emsp;&emsp;深度缓冲初始化为最大值（`FLT_MAX`），表示最远处。每个像素只保留最近的深度，实现自动的遮挡处理。

&emsp;&emsp;**深度冲突**（Z-Fighting）：当两个三角形深度非常接近时，由于浮点精度限制，深度比较可能出现闪烁。解决方案包括：
- 增大 $near/far$ 比值
- 使用对数深度缓冲
- 偏移深度值

## 3 光照系统

&emsp;&emsp;光照是让 3D 场景看起来真实的关键。没有光照，所有物体都只是平坦的颜色块。光照模型描述了光线如何与物体表面交互，产生明暗、高光、阴影等视觉效果。

&emsp;&emsp;本章介绍经典的 **Phong 光照模型**及其改进 **Blinn-Phong 模型**，这是实时渲染中最常用的光照模型。

### 3.1 光照模型概述

&emsp;&emsp;Phong 光照模型将光照分解为三个独立分量：

$$I = I_{ambient} + I_{diffuse} + I_{specular}$$

| 分量 | 物理含义 | 视觉效果 |
|------|---------|---------|
| **环境光**（Ambient） | 间接光照的近似 | 物体背光面不会全黑 |
| **漫反射**（Diffuse） | 光线在粗糙表面的均匀散射 | 物体的基本明暗 |
| **镜面反射**（Specular） | 光线在光滑表面的定向反射 | 高光点 |

### 3.2 环境光

&emsp;&emsp;在真实世界中，光线会在物体之间多次反射，形成间接光照。精确模拟间接光照需要全局光照算法（如光线追踪），计算成本极高。

&emsp;&emsp;环境光是间接光照的**简化近似**：假设场景中存在一个均匀的、无处不在的基础光照，确保物体背光面不会完全黑暗：

$$I_{ambient} = k_a \cdot L_a$$

&emsp;&emsp;其中：
- $k_a$：材质的环境光系数（通常为 $[0, 1]$ 的标量或 RGB 颜色）
- $L_a$：环境光颜色

```cpp
// 环境光计算
ColorFlt ambient = rig->ambientColor * rig->ambient;
result = result + ambient;
```

&emsp;&emsp;环境光的优点是计算简单，缺点是过于均匀，无法产生真实的明暗变化。通常需要配合漫反射和镜面反射使用。

![](https://cdn.jsdelivr.net/gh/grayondream/SoftGameEngine@develop/assets/imgs/07_soft_render_engine_sample_ambient_light.png)

### 3.3 漫反射（Lambert）

&emsp;&emsp;漫反射遵循 **Lambert 余弦定律**：光线照射到粗糙表面后，向各个方向均匀散射（理想漫反射体），观察到的亮度与入射角的余弦成正比。

&emsp;&emsp;数学表达：

$$I_{diffuse} = k_d \cdot L_d \cdot \max(0, N \cdot L)$$

&emsp;&emsp;其中：
- $k_d$：材质的漫反射系数（通常为纹理颜色）
- $L_d$：光源颜色和强度
- $N$：表面法线（单位向量，指向外侧）
- $L$：从表面指向光源的方向向量（单位向量）
- $\max(0, N \cdot L)$：确保背光面不产生负亮度

&emsp;&emsp;**为什么用余弦？** 想象一束光照射到表面。当光线垂直入射（$N \cdot L = 1$）时，光斑最小，能量最集中；当光线倾斜入射（$N \cdot L$ 接近 0）时，同样的光束散布在更大的区域，单位面积的能量更低。

```cpp
// 漫反射计算
Vector3D lightDir = (lightPos - fragPos).normalize();  // 指向光源
double diff = std::max(0.0, normal.dot(lightDir));
ColorFlt diffuse = lightColor * diff;
result = result + diffuse;
```

&emsp;&emsp;注意：`lightDir` 是从**表面指向光源**的方向，而光照公式中的 $L$ 也是这个方向。如果光源数据存储的是光线方向（从光源指向表面），需要取反。

### 3.4 镜面反射（Specular）

&emsp;&emsp;镜面反射产生**高光**效果，是光滑表面（如金属、塑料）的特征。与漫反射不同，镜面反射强烈依赖观察角度。

#### 3.4.1 Phong 模型

&emsp;&emsp;Phong 模型计算反射向量 $R$ 与观察方向 $V$ 的点积：

$$I_{specular} = k_s \cdot L_s \cdot \max(0, R \cdot V)^{shininess}$$

&emsp;&emsp;其中：
- $R$：光线关于法线的反射向量
- $V$：从表面指向相机的观察方向
- $shininess$：高光指数，值越大高光越集中（通常 2~256）

&emsp;&emsp;反射向量的计算：

$$R = 2 \cdot (N \cdot L) \cdot N - L$$

```cpp
// Phong 镜面反射
Vector3D R = 2.0 * normal.dot(lightDir) * normal - lightDir;
double spec = std::pow(std::max(0.0, R.dot(viewDir)), shininess);
```

#### 3.4.2 Blinn-Phong 改进

&emsp;&emsp;Blinn-Phong 模型使用**半程向量** $H$ 替代反射向量 $R$，计算更简单且效果更自然：

$$H = \text{normalize}(L + V)$$

$$I_{specular} = k_s \cdot L_s \cdot \max(0, N \cdot H)^{shininess}$$

&emsp;&emsp;半程向量是光源方向与观察方向的中间方向。当 $H$ 与法线 $N$ 对齐时，表示观察方向正好在反射方向上，高光最强。

```cpp
// Blinn-Phong 镜面反射
Vector3D H = (lightDir + viewDir).normalize();
double spec = std::pow(std::max(0.0, normal.dot(H)), shininess);
```

&emsp;&emsp;**为什么 Blinn-Phong 比 Phong 更好？**
1. 当光源在相机后方时，Phong 模型可能产生不正确的高光，Blinn-Phong 不会
2. Blinn-Phong 的高光形状更自然，边缘衰减更平滑
3. 计算反射向量 $R$ 需要额外的乘法和减法，而 $H$ 只需加法和归一化

### 3.5 完整 Blinn-Phong 着色

&emsp;&emsp;将三种光照分量组合，得到最终的 Blinn-Phong 着色模型：

$$I = k_a \cdot L_a + \sum_{lights} \left( k_d \cdot L_d \cdot \max(0, N \cdot L) + k_s \cdot L_s \cdot \max(0, N \cdot H)^{shininess} \right)$$

&emsp;&emsp;对于多种光源（方向光、点光源、聚光灯），需要分别计算每种光源的贡献，然后累加。

```cpp
// 实际 API：自由函数，按光照 rig + 反照率 + 法线 + 世界坐标 + 视点计算
uint32_t shade(const LightingRig &rig,        // 光照集合（ambient/shininess/光源列表）
               const Color32 &albedo,         // 表面反照率（漫反射颜色）
               const Vector3D &normal,        // 世界空间法线
               const Vector3D &P,             // 世界空间位置
               const Vector3D &viewPos,       // 相机位置
               double shadowFactor = 1.0);

uint32_t shade(const LightingRig &rig, const Color32 &albedo, const Vector3D &N,
               const Vector3D &P, const Vector3D &viewPos, double shadowFactor) {
    const Vector3D Nn = N.normalize();
    const Vector3D V = (viewPos - P).normalize();

    // Clamp01 = std::clamp(v, 0, 1)（引擎 Light.cpp 内部辅助函数）

    // 环境光 = ambient × ambientColor（不乘 shadowFactor）
    double diffR = rig.ambient * rig.ambientColor.r;
    double diffG = rig.ambient * rig.ambientColor.g;
    double diffB = rig.ambient * rig.ambientColor.b;
    double specR = 0, specG = 0, specB = 0;

    // 逐光源累加（衰减 × 阴影因子均乘入）
    auto accum = [&](const Vector3D &L, const ColorFlt &lc, double atten) {
        double ndotl = std::max(0.0, Nn.dot(L));     // Lambert 漫反射
        diffR += lc.r * ndotl * atten * shadowFactor;
        diffG += lc.g * ndotl * atten * shadowFactor;
        diffB += lc.b * ndotl * atten * shadowFactor;

        double sp;
        if (rig.blinnPhong) {
            // Blinn-Phong: 半程向量 N.H
            Vector3D H = (L + V).normalize();
            sp = std::pow(std::max(0.0, Nn.dot(H)), rig.shininess);
        } else {
            // 经典 Phong: 反射向量 R.V
            double ndl2 = 2.0 * Nn.dot(L);
            Vector3D R{ndl2 * Nn.x - L.x, ndl2 * Nn.y - L.y, ndl2 * Nn.z - L.z};
            sp = std::pow(std::max(0.0, R.dot(V)), rig.shininess);
        }
        sp *= rig.specularStrength * atten * shadowFactor;
        specR += lc.r * sp; specG += lc.g * sp; specB += lc.b * sp;
    };

    // 1. 方向光（引擎约定 direction 即"指向光源"，运行时 normalize，无衰减）
    for (auto &dl : rig.directional) {
        accum(dl.direction.normalize(), dl.color, 1.0);
    }

    // 2. 点光源（物理衰减或范围衰减，见 3.6.2）
    for (auto &pl : rig.point) {
        Vector3D diff = pl.position - P;
        double dist = diff.length();
        double atten;
        if (pl.quadratic > 0 || pl.linear > 0) {
            // 物理衰减
            atten = 1.0 / (1.0 + pl.linear * dist + pl.quadratic * dist * dist);
        } else {
            // 范围线性衰减：linear/quadratic 均为 0 时按 range 线性衰减到 0
            if (pl.range <= 0) continue;
            atten = Clamp01(1.0 - dist / pl.range);
        }
        if (atten <= 0) continue;
        accum(diff.normalize(), pl.color, atten);
    }

    // 3. 聚光灯（距离衰减 × 锥形衰减，见 3.6.3）
    for (auto &sl : rig.spot) {
        Vector3D diff = sl.position - P;
        double dist = diff.length();
        if (dist < 1e-9) continue;
        // 距离衰减：启用软边(outerCutoffCos > -0.999)或未设 range 时用
        // 固定物理衰减；否则按 range 范围线性衰减到 0
        double atten;
        if (sl.outerCutoffCos > -0.999 || sl.range <= 0) {
            atten = 1.0 / (1.0 + 0.09 * dist + 0.032 * dist * dist);
        } else {
            atten = Clamp01(1.0 - dist / sl.range);
        }
        if (atten <= 0) continue;
        Vector3D L = diff / dist;
        double cosAng = L.dot((-sl.direction).normalize());
        // 锥形衰减：软边在内外锥角余弦间线性插值 + (2-edge)*edge 平滑；
        // 硬边（未启用软边）在外锥外直接熄灭
        double edge;
        if (sl.outerCutoffCos > -0.999 && sl.outerCutoffCos > sl.cutoffCos) {
            edge = Clamp01((cosAng - sl.outerCutoffCos)
                / std::max(1e-4, sl.cutoffCos - sl.outerCutoffCos));
        } else {
            if (cosAng < sl.cutoffCos) continue;
            edge = Clamp01((cosAng - sl.cutoffCos)
                / std::max(1e-4, 1.0 - sl.cutoffCos));
        }
        if (edge <= 0) continue;
        accum(L, sl.color, atten * (edge * (2.0 - edge)));
    }

    // 最终颜色 = albedo/255 × 光累加 + 高光累加
    return Pack(255,
        ch(albedo.r, diffR, specR), ch(albedo.g, diffG, specG), ch(albedo.b, diffB, specB));
}
```

### 3.6 光源类型

#### 3.6.1 方向光（Directional Light）

&emsp;&emsp;方向光模拟**无限远处**的光源（如太阳），所有光线方向平行，无距离衰减。

&emsp;&emsp;方向光只需要两个参数：
- **方向**：光线的方向向量（指向光源）
- **颜色**：光线的颜色和强度

```cpp
struct DirectionalLight {
    Vector3D direction;      // 指向光源的方向（引擎约定方向即"指向光源"，运行时 normalize）
    ColorFlt color{1.0, 1.0, 1.0, 1.0};
};
```

&emsp;&emsp;方向光的特点：
- 光线方向恒定，与物体位置无关
- 无距离衰减（太阳光近似平行）

#### 3.6.2 点光源（Point Light）

&emsp;&emsp;点光源从一个点向**四周发光**（如灯泡），亮度随距离衰减。

&emsp;&emsp;衰减公式遵循物理规律：

$$attenuation = \frac{1}{1 + linear \cdot d + quadratic \cdot d^2}$$

&emsp;&emsp;其中 $d$ 是到光源的距离。常用参数：

| 范围 | 常数 | 线性项 | 二次项 |
|------|------|--------|--------|
| 7 | 1.0 | 0.7 | 1.8 |
| 13 | 1.0 | 0.35 | 0.44 |
| 20 | 1.0 | 0.22 | 0.20 |
| 32 | 1.0 | 0.14 | 0.07 |
| 50 | 1.0 | 0.09 | 0.032 |
| 65 | 1.0 | 0.07 | 0.017 |
| 100 | 1.0 | 0.045 | 0.0075 |
| 200 | 1.0 | 0.022 | 0.0019 |

```cpp
struct PointLight {
    Vector3D position;
    ColorFlt color{1.0, 1.0, 1.0, 1.0};
    double linear{0.0};      // 线性衰减系数（默认 0，即无物理衰减）
    double quadratic{0.0};   // 二次衰减系数
    double range{10.0};      // 最大影响范围（仅当无物理衰减时用线性衰减到 0）
};
```

&emsp;&emsp;点光源的衰减有两种模式（引擎按 `linear`/`quadratic` 是否为 0 自动选择）：
- 设置 `linear`/`quadratic` 时采用**物理衰减** $\frac{1}{1 + linear \cdot d + quadratic \cdot d^2}$（参考 LearnOpenGL 表）
- 均为 0 时采用**范围线性衰减** $\text{clamp}\left(1 - \frac{d}{range}, 0, 1\right)$

&emsp;&emsp;常用的物理衰减参数（LearnOpenGL 标准表，`PointLightScene` 使用 50 范围一行 1.0/0.09/0.032）：

| 范围 | 常数 | 线性项 | 二次项 |
|------|------|--------|--------|
| 7 | 1.0 | 0.7 | 1.8 |
| 13 | 1.0 | 0.35 | 0.44 |
| 20 | 1.0 | 0.22 | 0.20 |
| 32 | 1.0 | 0.14 | 0.07 |
| 50 | 1.0 | 0.09 | 0.032 |
| 65 | 1.0 | 0.07 | 0.017 |
| 100 | 1.0 | 0.045 | 0.0075 |
| 200 | 1.0 | 0.022 | 0.0019 |

#### 3.6.3 聚光灯（Spot Light）

&emsp;&emsp;聚光灯结合了方向光和点光源的特性，有一个**锥形照射范围**（如手电筒）。

&emsp;&emsp;聚光灯有两个锥角：
- **内锥角**（Inner Cutoff）：完全照亮的区域
- **外锥角**（Outer Cutoff）：内锥角到外锥角之间，亮度逐渐衰减（软边）

$$\text{intensity} = \frac{\theta - \text{outerCutoff}}{\text{innerCutoff} - \text{outerCutoff}}$$

&emsp;&emsp;其中 $\theta$ 是片段方向与聚光灯方向的夹角余弦值。

```cpp
struct SpotLight {
    Vector3D position;
    Vector3D direction;             // 聚光灯朝向
    ColorFlt color{1.0, 1.0, 1.0, 1.0};
    double range{12.0};              // 照射范围
    double cutoffCos{0.85};          // 内锥角余弦（全亮）
    double outerCutoffCos{-1.0};     // 外锥角余弦（-1.0 表示硬边，无软衰减）
};
```

&emsp;&emsp;聚光灯有**内锥角**（`cutoffCos`，完全照亮）与**外锥角**（`outerCutoffCos`，软边外完全熄灭）。`outerCutoffCos > -0.999` 时启用软边，否则为硬边。参考场景使用内锥 12.5°（cos≈0.976）与外锥 17.5°（cos≈0.954），并将软边阈值显式设置为余弦值。

&emsp;&emsp;聚光灯的衰减 = 距离衰减 × 锥形衰减：

```cpp
// 聚光灯衰减计算（与 3.5 节 shade() 的完整分支一致）
// 距离衰减：启用软边(outerCutoffCos > -0.999)或未设 range 时用固定
// 物理衰减 1/(1+0.09d+0.032d²)；否则按 range 范围线性衰减到 0
double dist = length(sl.position - P);
double attenuation;
if (sl.outerCutoffCos > -0.999 || sl.range <= 0) {
    attenuation = 1.0 / (1.0 + 0.09 * dist + 0.032 * dist * dist);
} else {
    attenuation = Clamp01(1.0 - dist / sl.range);
}

// 锥形衰减（cosAng = 片段方向 与 -direction 的余弦）
double cosAng = normalize(P - sl.position).dot((-sl.direction).normalize());
double edge;
if (sl.outerCutoffCos > -0.999 && sl.outerCutoffCos > sl.cutoffCos) {
    edge = clamp((cosAng - sl.outerCutoffCos)
              / max(1e-4, sl.cutoffCos - sl.outerCutoffCos), 0.0, 1.0);
    edge = edge * (2.0 - edge);   // smoothstep 平滑（二次近似），消除锥边突变
} else {
    // 硬边：外锥外直接熄灭
    if (cosAng < sl.cutoffCos) return 0;
    edge = clamp((cosAng - sl.cutoffCos)
              / max(1e-4, 1.0 - sl.cutoffCos), 0.0, 1.0);
}

double totalAttenuation = attenuation * edge;
```

### 3.7 材质系统

&emsp;&emsp;材质定义了物体表面对光的响应特性。不同的材质参数产生不同的视觉效果（金属、塑料、木材等）。

&emsp;&emsp;SoftGameEngine 中，材质参数分为两层：

- **`LightingRig`**：全局光照参数（环境光强度 `ambient`、环境光颜色 `ambientColor`、高光指数 `shininess`、高光强度 `specularStrength`）
- **`Color32 albedo`**：每个物体表面的漫反射颜色（在 `shade()` 中作为反照率参与计算）

```cpp
struct LightingRig {
    float ambient{0.15f};              // 环境光强度
    ColorFlt ambientColor{1.0f, 1.0f, 1.0f, 1.0f};  // 环境光颜色
    float shininess{32.0f};            // 高光指数
    float specularStrength{0.5f};      // 高光强度缩放
    bool blinnPhong{true};             // true=Blinn-Phong, false=经典 Phong
    std::vector<DirectionalLight> directional{};
    std::vector<PointLight> point{};
    std::vector<SpotLight> spot{};
};

// PBR 材质见 7.1 节
struct PbrMaterial {
    Color32 baseColor{200, 60, 60, 255};
    float metallic{0.0f};
    float roughness{0.35f};
    float ao{1.0f};
    const Texture *albedoTex{}, *metallicTex{}, *roughnessTex{};
};
```

&emsp;&emsp;**高光指数**（shininess）控制高光的大小和集中度：
- 值越大，高光越小越亮（如抛光金属）
- 值越小，高光越大越暗（如磨砂表面）

### 3.8 光照贴图

&emsp;&emsp;光照贴图（Lighting Maps）通过纹理为物体表面不同区域提供不同的漫反射颜色与高光强度（对应 LearnOpenGL 的 "lighting maps" 概念，非预计算全局光照）。

&emsp;&emsp;常见的光照贴图类型：

| 贴图类型 | 存储内容 | 用途 |
|---------|---------|------|
| **漫反射贴图**（Diffuse Map） | 表面颜色 | 提供物体的基本颜色 |
| **高光贴图**（Specular Map） | 高光强度 | 控制不同区域的高光强度 |
| **法线贴图**（Normal Map） | 表面法线细节 | 增加凹凸感（见 6.2 节） |

```cpp
// 漫反射贴图提供表面颜色
uint32_t diffuse = diffuseTex.sample(u, v);

// 高光贴图控制高光区域（灰度图，引擎取蓝通道作遮罩，白色=强高光，黑色=无高光）
double specStrength = (specTex.sample(u, v) & 0xFF) / 255.0;

// 最终高光强度 = 材质高光强度 × 高光贴图
double finalSpec = shading.specularStrength * specStrength;
```

## 4 模型加载

&emsp;&emsp;在实际项目中，3D 模型通常由美术人员使用建模软件（如 Blender、Maya）创建，导出为标准格式后由引擎加载。SoftGameEngine 支持 **Wavefront OBJ** 格式，这是最简单且广泛使用的 3D 模型格式。

### 4.1 OBJ 格式解析

&emsp;&emsp;Wavefront OBJ 是一种纯文本格式，以行为单位存储几何数据。SoftGameEngine 实现了完整的 OBJ 加载器：

```cpp
// 实际 API：将 OBJ 解析结果直接写入 Object4D（vlistLocal/plist）
bool loadObjFromFile(const std::string &path, Object4D &out);

    std::vector<std::string> names;      // 材质出现顺序
    std::vector<std::string> diffuseMap; // 每材质 map_Kd 文件名（无则空串）
    std::string mtlDir;                  // mtl 与贴图所在目录
};
bool loadObjMultiMaterial(const std::string &path,
                          std::vector<Object4D> &chunks,
                          std::vector<int> &faceMaterial,
                          ObjMaterialInfo &materials);
```

#### 4.1.1 OBJ 文件格式

&emsp;&emsp;OBJ 文件以行为单位，每行以关键字开头：

```
## 这是注释
mtllib model.mtl          ## 引用材质库

v  1.0  2.0  3.0         ## 顶点位置 (x, y, z)
v  0.5  1.5  2.5
v  1.5  1.5  2.5

vt 0.0  0.0               ## 纹理坐标 (u, v)
vt 1.0  0.0
vt 0.5  1.0

vn 0.0  0.0  1.0          ## 法线 (nx, ny, nz)
vn 0.0  0.0  1.0
vn 0.0  0.0  1.0

usemtl copper              ## 使用材质

f 1/1/1 2/2/1 3/3/1       ## 三角形面 (位置索引/纹理索引/法线索引)
f 1/1/1 3/3/1 4/4/1
```

#### 4.1.2 索引格式

&emsp;&emsp;OBJ 支持四种面索引格式：

| 格式 | 示例 | 说明 |
|------|------|------|
| `f v` | `f 1 2 3` | 仅位置索引 |
| `f v/vt` | `f 1/1 2/2 3/3` | 位置 + 纹理坐标 |
| `f v/vt/vn` | `f 1/1/1 2/2/2 3/3/3` | 位置 + 纹理 + 法线 |
| `f v//vn` | `f 1//1 2//2 3//3` | 位置 + 法线（无纹理） |

&emsp;&emsp;索引从 **1** 开始（非 0），支持**负索引**（从末尾倒数）。

#### 4.1.3 解析实现

&emsp;&emsp;OBJ 解析的核心是按行读取，根据关键字分发处理。真实实现还包含 UTF-8 BOM 剥离、`\r` 去除、顶点/UV/法线数量上限（各 4096，顶点另有 `kObject4vListLen`）与失败清零等防御逻辑：

```cpp
bool loadObjFromFile(const std::string &path, Object4D &out) {
    out.numVertices = 0; out.numPolys = 0;   // 失败时清零
    std::ifstream file(path);
    if(!file.is_open()) return false;

    std::vector<Point4D> verts;      // 顶点 (v)  → Point4D{x, y, z, 1}
    std::vector<UV2D> uvs;           // 纹理坐标 (vt)
    std::vector<Vector3D> normals;   // 法线 (vn)

    bool firstLine = true;
    std::string line;
    while(std::getline(file, line)){
        if(firstLine){               // 剥离 UTF-8 BOM
            firstLine = false;
            if(line.size() >= 3 && (unsigned char)line[0] == 0xEF
               && (unsigned char)line[1] == 0xBB && (unsigned char)line[2] == 0xBF)
                line.erase(0, 3);
        }
        if(!line.empty() && line.back() == '\r') line.pop_back();
        std::istringstream ss(line);
        std::string tag;
        if(!(ss >> tag)) continue;

        if(tag == "v"){
            double x, y, z; if(!(ss >> x >> y >> z)) return false;
            if(verts.size() >= kObject4vListLen) return false;
            verts.push_back(Point4D{x, y, z, 1});
        }else if(tag == "vt"){
            double u, v; if(!(ss >> u >> v)) return false;
            if(uvs.size() >= kMaxObjUVs) return false;
            uvs.push_back(UV2D{u, v});
        }else if(tag == "vn"){
            double x, y, z; if(!(ss >> x >> y >> z)) return false;
            if(normals.size() >= kMaxObjNormals) return false;
            normals.push_back(Vector3D{x, y, z});
        }else if(tag == "f"){
            std::vector<ObjVertexRef> refs;   // 解析 v/vt/vn 三元组
            std::string tok;
            while(ss >> tok){
                ObjVertexRef ref;
                if(!ParseVertexRef(tok, ref)) return false;
                refs.push_back(ref);
            }
            // ResolveIndex 处理正索引(-1)与负索引(从末尾倒数)
            // fan 三角化：refs[0] + refs[i] + refs[i+1] 逐面写入 plist
        }
    }
    return true;
}
```

### 4.3 模型图集

&emsp;&emsp;对于多材质模型（如 backpack，包含多个部件），每个部件可能使用不同的纹理。如果每个部件单独绑定纹理，会导致频繁的纹理切换，影响性能。

&emsp;&emsp;SoftGameEngine 将所有漫反射贴图打包为**图集**（Atlas），避免频繁切换纹理：

```cpp
struct AtlasTile { double u0, v0, u1, v1; };  // 每材质的归一化区域
struct DiffuseAtlas {
    Texture texture{};
    std::vector<AtlasTile> tiles;   // 按材质索引
    bool valid{false};
};

// 实际 API：从 MTL 材质信息构建，固定 2 行网格，最近邻重采样到 256px 单元
DiffuseAtlas BuildDiffuseAtlas(const ObjMaterialInfo &materials) {
    DiffuseAtlas out;
    int count = materials.names.size();
    int cols = (count + 1) / 2;    // 固定 2 行布局
    int rows = 2;
    constexpr int kCell = 256;
    int aw = cols * kCell, ah = rows * kCell;
    std::vector<uint32_t> pixels(aw * ah, 0xFF9A9A9Au);

    for(int m = 0; m < count; m++){
        int cx = m % cols, cy = m / cols;
        // 加载贴图（无 map_Kd 时用灰底占位）
        Texture tex = materials.diffuseMap[m].empty()
            ? Texture(1, 1, {0xFFB0B0B0u})
            : ImageLoader::loadTexture(materials.mtlDir + "/" + materials.diffuseMap[m]);
        // 最近邻重采样到 256×256 单元格
        for(int py = 0; py < kCell; py++)
            for(int px = 0; px < kCell; px++){
                int sx = std::min(tex.width() - 1, px * tex.width() / kCell);
                int sy = std::min(tex.height() - 1, py * tex.height() / kCell);
                pixels[(cy*kCell+py)*aw + cx*kCell+px] =
                    tex.sample((sx+0.5)/tex.width(), (sy+0.5)/tex.height(),
                               TextureFilter::Nearest, TextureWrap::Clamp);
            }
        // 记录该材质的图集区域
        out.tiles.push_back({double(cx)*kCell/aw, double(cy)*kCell/ah,
                             double(cx+1)*kCell/aw, double(cy+1)*kCell/ah});
    }
    out.texture = Texture(aw, ah, pixels.data());
    out.valid = true;
    return out;
}
```

#### 4.3.1 图集的优势

- **减少纹理切换**：整个模型只需绑定一次纹理
- **提高缓存命中率**：相邻三角形的纹理数据在内存中连续
- **渲染代码简化**：采样时按 `tile` 区域重映射 UV

&emsp;&emsp;UV 重映射在场景层单独完成：维护**每面材质索引**数组（`m_faceMtl`），绘制时将原始 UV 按对应材质的 `tile` 区域缩放平移到图集坐标：

```cpp
// LoadModel 场景：每面按材质把 UV 映射到图集区域
for(int i = 0; i < (int)tr.size(); i++){
    int mat = faceMaterial[i];
    AtlasTile tile = atlas.tiles[mat];
    ScreenVertex a = tr[i].v[0], b = tr[i].v[1], c = tr[i].v[2];
    a.u = tile.u0 + a.u * (tile.u1 - tile.u0); a.v = tile.v0 + a.v * (tile.v1 - tile.v0);
    b.u = tile.u0 + b.u * (tile.u1 - tile.u0); b.v = tile.v0 + b.v * (tile.v1 - tile.v0);
    c.u = tile.u0 + c.u * (tile.u1 - tile.u0); c.v = tile.v0 + c.v * (tile.v1 - tile.v0);
    rz.drawTriangleTextured(a, b, c, atlas.texture, &ctx);
}
```

#### 4.3.2 图集的限制

- **纹理分辨率损失**：重采样会降低细节
- **内存浪费**：未使用的区域仍占用显存
- **UV 边界问题**：需要处理纹理接缝

## 5 高级特性

&emsp;&emsp;本章介绍软渲染引擎的高级特性，包括深度测试、Alpha 混合、背面剔除、后处理、天空盒等。这些特性让渲染结果更加真实和完整。

### 5.1 深度测试

&emsp;&emsp;深度测试（Depth Test）解决物体遮挡问题：确保近处物体正确遮挡远处物体。这是通过**深度缓冲**（Z-Buffer）实现的。

#### 5.1.1 深度缓冲原理

&emsp;&emsp;深度缓冲是一个与颜色缓冲同样大小的数组，每个像素存储该位置最近物体的深度值。当绘制新像素时：

1. 读取深度缓冲中存储的深度值 $z_{buffer}$
2. 比较当前像素的深度值 $z_{pixel}$
3. 如果 $z_{pixel} < z_{buffer}$（更近），则更新颜色缓冲和深度缓冲
4. 如果 $z_{pixel} \geq z_{buffer}$（更远），则跳过该像素

#### 5.1.2 深度值映射

&emsp;&emsp;引擎主渲染 pass 的深度缓冲直接存储 NDC 深度（透视校正插值后），深度测试仅需单调比较，无需映射；仅**阴影深度贴图**需要将 $[-1,1]$ 映射到 $[0,1]$ 以便与光源空间比较（见 6.1 节）。缓冲初始化为最大值（`FLT_MAX`）：

```cpp
// 主 pass：透视校正插值得到 NDC 深度（直接比较，未映射）
float zNdc = (w0 * v0.z / v0.w + w1 * v1.z / v1.w + w2 * v2.z / v2.w) / iw;

// 深度测试
auto idx = y * width + x;
if (zNdc < m_depth[idx]) {                     // 更近
    m_depth[idx] = zNdc;                       // 更新深度
    m_color[idx] = bgra;                       // 更新颜色
}

// 仅阴影深度贴图使用：[-1,1] → [0,1] 映射
float z01 = zNdc * 0.5f + 0.5f;
```

#### 5.1.3 深度可视化

&emsp;&emsp;将深度值可视化为灰度图像，可以帮助调试深度测试问题：

```cpp

uint8_t gray = static_cast<uint8_t>(depth * 255);

```

&emsp;&emsp;在可视化中：
- **黑色**（0）：最近的物体
- **白色**（255）：最远的物体
- **灰色**：中间深度

### 5.2 Alpha 混合

&emsp;&emsp;Alpha 混合实现**半透明效果**。对于半透明物体，需要将前景颜色与背景颜色按透明度混合。

#### 5.2.1 Source-Over 合成

&emsp;&emsp;最常用的混合公式是 **Source-Over**：

$$C_{result} = C_{src} \cdot \alpha_{src} + C_{dst} \cdot (1 - \alpha_{src})$$

&emsp;&emsp;其中：
- $C_{src}$：源颜色（当前要绘制的像素）
- $\alpha_{src}$：源透明度（0=完全透明，255=完全不透明）
- $C_{dst}$：目标颜色（帧缓冲中已有的颜色）

#### 5.2.2 混合实现

```cpp
void FrameBuffer::blendPixel(size_t x, size_t y, uint32_t bgra, float depth) {
    if (x >= m_width || y >= m_height) return;
    if (!std::isfinite(depth)) return;

    uint32_t sa = (bgra >> 24) & 0xFF;       // 源 alpha
    if (sa == 0) return;                       // 完全透明，跳过

    auto idx = y * m_width + x;
    if (depth >= m_depth[idx]) return;         // 被遮挡，跳过

    if (sa == 255) {
        // 完全不透明：直接覆写
        m_depth[idx] = depth;
        m_color[idx] = bgra;
        return;
    }

    // 半透明：src-over 混合（引擎不混合 alpha，输出恒为 0xFF 不透明）
    uint32_t dst = m_color[idx];
    auto mix = [sa](uint32_t s, uint32_t d){
        return (s * sa + d * (255u - sa) + 127u) / 255u;  // +127 四舍五入
    };
    uint32_t outR = mix((bgra >> 16) & 0xFF, (dst >> 16) & 0xFF);
    uint32_t outG = mix((bgra >> 8) & 0xFF, (dst >> 8) & 0xFF);
    uint32_t outB = mix(bgra & 0xFF, dst & 0xFF);

    m_depth[idx] = depth;
    m_color[idx] = 0xFF000000u | (outR << 16) | (outG << 8) | outB;
}
```

&emsp;&emsp;限制：混合后的像素 alpha 恒为 `0xFF`（不透明），丢弃了前景 alpha 的累积。本引擎的最终输出不再需要帧缓冲级透明合成（UI 叠加走 `setPixelOverlay` 无条件覆写），因此该限制可接受；若后续需要在帧缓冲上继续做透明合成（如多层半透明 UI），需改为输出加权 alpha $a_{out} = a_s + a_d(1-a_s)$。

#### 5.2.3 画家算法

&emsp;&emsp;透明物体需要**从远到近排序**（画家算法），确保混合顺序正确。如果混合顺序错误，透明效果会出现错误。

```cpp
// 实际 API：返回按"远在前"排序的索引数组
template<class PosFn>
std::vector<int> SortFarToNear(int count, PosFn positionOf, const Vector3D &eye) {
    std::vector<int> order(count);
    for(int i = 0; i < count; i++) order[i] = i;
    std::sort(order.begin(), order.end(), [&](int a, int b){
        double da = positionOf(a).distanceSquared(eye);
        double db = positionOf(b).distanceSquared(eye);
        return da > db;   // 远的在前
    });
    return order;
}
```

&emsp;&emsp;画家算法的局限性：当两个透明物体相互穿插时，简单的排序无法正确处理。这种情况下需要使用**顺序无关透明**（OIT）算法。

### 5.3 背面剔除

&emsp;&emsp;对于封闭物体，背面三角形永远不可见，可以提前剔除以节省光栅化开销。

#### 5.3.1 背面判定

&emsp;&emsp;通过判断三角形在屏幕空间的**有向面积**来确定正面/背面：

```cpp
bool Pipeline::isBackFacing(const ScreenVertex &a, const ScreenVertex &b,
                           const ScreenVertex &c) {
    double area = (b.x - a.x) * (c.y - a.y) - (b.y - a.y) * (c.x - a.x);
    return area < 0;  // 负面积为背面（取决于顶点绕序和y轴方向）
}
```

#### 5.3.2 顶点绕序

&emsp;&emsp;正面/背面由顶点的**绕序**（Winding Order）决定：

| 绕序 | 正面 | 背面 |
|------|------|------|
| 逆时针（CCW） | 从正面看，顶点逆时针排列 | 从正面看，顶点顺时针排列 |
| 顺时针（CW） | 从正面看，顶点顺时针排列 | 从正面看，顶点逆时针排列 |

&emsp;&emsp;约定：**模型/世界空间采用顺时针（CW）绕序为正面**（DirectX/Vulkan 约定，与 OpenGL 默认的逆时针 CCW 相反）——即从正面（外侧）观察时顶点按顺时针排列，几何叉积法线指向实体内侧；顶点法线数组 `nlist` 单独存储外侧法线供光照使用。本引擎几何体（`MakeCube`/`MakeSphere`/`makePlane`）均按此绕序构建。

&emsp;&emsp;从模型空间到屏幕空间的符号链：`lookAt`（右手系）与透视投影不改变投影面上的有向面积符号，故正面三角形在视图/NDC 空间（$y$ 向上）表现为顺时针、有向面积为**负**；视口映射将 $y$ 翻转为 y-down 屏幕空间，有向面积再取反，最终正面三角形在屏幕空间的有向面积为**正**（front=POS），等价于 y-down 坐标系中的顺时针绕序。`SceneUtil::makePlane` 注释明言 "front=POS after the y flip"。

#### 5.3.3 背面剔除的条件

&emsp;&emsp;背面剔除只适用于**封闭物体**（水密的）。管线 `projectObject` 始终对每个三角形执行 `isBackFacing` 剔除，开放曲面（如地面、布料）依靠**正面绕序**保留；光栅化阶段的 `Rasterizer::cullBackface` 开关（默认关闭）只影响 `drawTriangle*` 系列函数：

```cpp
rz.cullBackface = true;   // 启用背面剔除（封闭物体）
rz.cullBackface = false;  // 禁用背面剔除（默认）
```

### 5.4 帧缓冲后处理

&emsp;&emsp;后处理（Post-Processing）是在渲染完成后，对帧缓冲中的图像进行各种效果处理。

#### 5.4.1 反相

&emsp;&emsp;反相将每个颜色通道取反（255 - 原值）：

```cpp
// 反相
color.r = 255 - color.r;
color.g = 255 - color.g;
color.b = 255 - color.b;
// 或简写为: color = ~color;
```

#### 5.4.2 灰度化

&emsp;&emsp;灰度化将彩色图像转换为灰度，使用人眼对不同颜色的敏感度加权：

```cpp
// 灰度化（BT.709 标准，与引擎 FrameBuffer 场景一致）
uint8_t gray = static_cast<int>(0.2126 * r + 0.7152 * g + 0.0722 * b);
color = {gray, gray, gray, color.a};
```

&emsp;&emsp;权重依据：人眼对绿色最敏感（71.5%），其次是红色（21.3%），蓝色最不敏感（7.2%）。

#### 5.4.3 锐化

&emsp;&emsp;锐化通过卷积核增强边缘对比度：

```
锐化卷积核（引擎使用 3×3 全 -1、中心 9）：
-1  -1  -1
-1   9  -1
-1  -1  -1
```

&emsp;&emsp;卷积核中心值为 9，周围为 -1，这使得每个像素与其 3×3 邻域的差异被放大，产生锐化效果。后处理在**拷贝的源缓冲**上进行卷积（避免读写同一缓冲造成结果污染）：

```cpp
// 锐化卷积（源缓冲 src 拷贝后原地写回）
static const int k[3][3] = {{-1,-1,-1},{-1,9,-1},{-1,-1,-1}};
for (int y = 0; y < h; y++) {
    for (int x = 0; x < w; x++) {
        double sum = 0;
        for (int ky = 0; ky < 3; ky++)
            for (int kx = 0; kx < 3; kx++)
                sum += k[ky][kx] * at(x + kx - 1, y + ky - 1);
        set(x, y, clamp(sum));
    }
}
```

### 5.5 天空盒

&emsp;&emsp;天空盒（Skybox）使用六面纹理模拟远处环境，产生无限远的背景效果。

#### 5.5.1 立方体贴图采样

&emsp;&emsp;天空盒的核心是**立方体贴图采样**：给定一个 3D 方向向量，确定采样的面和 UV 坐标。

```cpp
// 实际签名：faces 为 6 个纹理指针数组（right,left,top,bottom,front,back）
Color32 SampleCubemap(const Vector3D &dir, const Texture *const *faces) {
    // 1. 确定主轴（绝对值最大的分量）
    double absX = std::abs(dir.x), absY = std::abs(dir.y), absZ = std::abs(dir.z);
    int face;
    double u, v;

    if (absX >= absY && absX >= absZ) {
        // ±X 面
        face = (dir.x > 0) ? 0 : 1;
        u = -dir.z / absX;
        v = -dir.y / absX;
        if (dir.x < 0) u = -u;   // 负面需翻转 U
    } else if (absY >= absX && absY >= absZ) {
        // ±Y 面
        face = (dir.y > 0) ? 2 : 3;
        u = dir.x / absY;
        v = dir.z / absY;
    } else {
        // ±Z 面
        face = (dir.z > 0) ? 4 : 5;
        u = dir.x / absZ;
        v = -dir.y / absZ;
        if (dir.z < 0) u = -u;   // 负面需翻转 U
    }

    // 2. 将 [-1,1] 映射到 [0,1] 并钳制到 [0, 0.99999]（防采样越界）
    u = std::clamp(u * 0.5 + 0.5, 0.0, 0.99999);
    v = std::clamp(v * 0.5 + 0.5, 0.0, 0.99999);

    // 3. 采样对应面的纹理（Bilinear + Clamp）
    return faces[face]->sample(u, v, TextureFilter::Bilinear, TextureWrap::Clamp);
}
```

&emsp;&emsp;说明：立方体贴图的 UV 翻转规则随引擎约定而异（OpenGL/DX 对负 X、负 Z 面的 U/V 翻转定义不同）。引擎采用上述约定：仅对负 X 与负 Z 面翻转 $u$，$v$ 方向不额外翻转——在自制 6 面贴图（非外部 cubemap 资产）下保持各面纹理连续即可，接入外部资产时需按资产约定同步调整。

#### 5.5.2 程序化天空

&emsp;&emsp;SoftGameEngine 还支持程序化环境（`SampleEnvironment`，无需外部纹理）：地平线以上为**渐变天空**，地平线以下为**投影网格地板**。

```cpp
Color32 SampleEnvironment(const Vector3D &dir) {
    const Vector3D d = EnvNormalize(dir);
    if (d.y >= 0.0) {
        // 渐变天空：随仰角线性增亮
        double t = d.y;
        int r = 40 + 60 * t, g = 80 + 120 * t, b = 160 + 90 * t;
        return Color32{min(r,255), min(g,255), min(b,255), 255};
    }
    // 网格地板：透视投影到地面平面 + 线检测 + 棋盘格明暗
    double fx = d.x / (-d.y), fz = d.z / (-d.y);
    double gx = fx * 6.0, gz = fz * 6.0;
    bool line = (std::abs(gx - std::floor(gx)) < 0.06) ||
                (std::abs(gz - std::floor(gz)) < 0.06);
    if (line) return Color32{200, 200, 210, 255};
    int shade = ((int)std::floor(gx) + (int)std::floor(gz)) % 2 == 0 ? 70 : 110;
    return Color32{shade, shade + 10, shade + 20, 255};
}
```

### 5.6 法线可视化

&emsp;&emsp;法线可视化将每个顶点的法线绘制为线段，帮助调试几何数据。法线方向应该正确指向外侧，否则会导致光照计算错误。

```cpp
// ① 球体用红色线框绘制（drawTriangleWireframe）
// ② 法线：世界空间下，顶点与法线端点都经同一模型矩阵变换后投影绘制
for (int i = 0; i < sphere.numVertices; i += 2) {
    const auto &sv = sphere.vlistLocal[i];
    Vector3D n{sv.x, sv.y, sv.z};      // 球心到顶点的方向即法线
    if (n.length() < 1e-9) continue;
    n = n.normalize();

    // 顶点经模型矩阵变换到世界空间
    Point4D p0 = sm * sv;
    // 法线端点 = 顶点 + 法线 × mag×2（mag=0.4）
    Point4D p1{p0.x + n.x * 0.8, p0.y + n.y * 0.8, p0.z + n.z * 0.8, 1};

    ScreenVertex a, b;
    if (!projectWorldPoint(vp, p0, W, H, a)) continue;
    if (!projectWorldPoint(vp, p1, W, H, b)) continue;
    a.color = b.color = Color32{255, 255, 0, 255};  // 黄色法线
    rz.drawLine(a, b);
}
```

### 5.7 几何着色器模拟

&emsp;&emsp;虽然 CPU 没有硬件几何着色器，但可以通过**顶点位移**模拟效果。爆炸效果沿法线方向移动顶点，产生"爆炸"动画。

#### 5.7.1 爆炸效果原理

&emsp;&emsp;引擎沿**每个三角形自己的面法线**（叉积计算，非顶点法线）方向外推顶点：

```cpp
// 沿面法线方向偏移顶点
for (int pi = 0; pi < boom.numPolys; pi++) {
    auto &poly = boom.plist[pi];
    // 叉积计算面法线
    Vector3D e1 = poly.vlist[1] - poly.vlist[0];
    Vector3D e2 = poly.vlist[2] - poly.vlist[0];
    Vector3D n{e1.y*e2.z - e2.y*e1.z, e2.x*e1.z - e1.x*e2.z,
               e1.x*e2.y - e2.x*e1.y};
    if (n.length() > 1e-12) {
        n = n.normalize() * mag;
        for (int k = 0; k < 3; k++) {
            poly.vlist[k].x += n.x;
            poly.vlist[k].y += n.y;
            poly.vlist[k].z += n.z;
        }
    }
}
```

&emsp;&emsp;前提：叉积方向取决于三角形顶点绕序。若模型绕序不一致（混有 CW 与 CCW），部分面法线会指向内侧导致爆炸方向错误。本场景使用 `MakeSphere`（球面三角形绕序统一），可保证所有面法线一致朝外。

#### 5.7.2 动画控制

&emsp;&emsp;爆炸效果使用正弦函数控制外推幅度（振幅 0~2），产生"呼吸"效果：

```cpp
// 幅度：0~2 周期变化
double mag = 2.0 * ((std::sin(app.angle()) + 1.0) / 2.0);
```

### 5.8 实例化渲染

&emsp;&emsp;实例化渲染（Instanced Rendering）允许一次绘制多个相同几何体，只需传递不同的变换矩阵。

#### 5.8.1 实例化的优势

- **减少绘制调用**：一次调用绘制多个物体
- **共享几何数据**：所有实例共享同一份顶点数据
- **GPU 友好**：可以利用 GPU 的并行能力

#### 5.8.2 实现方式

&emsp;&emsp;`MultiInstanceScene` 绘制 **100 个球体实例**（10×10 网格），每个实例独立变换、线框绘制、红色随 id 递增：

```cpp
// 生成 100 个球体实例（10×10 网格，参考布局）
int id = 0;
for (int ox = 0; ox < 10; ox++) {
    for (int oy = 0; oy < 10; oy++) {
        if (id >= 100) break;
        Object4D ball = proto;
        double sc = 0.35 + 0.15 * (id % 10) / 9.0;   // 尺寸随列增长
        auto bm = SGE::Math::translation(ox * 1.3 - 5.85, oy * 1.3 - 5.85, -8)
            .mul(SGE::Math::scale(sc, sc, sc));
        auto bnrm = SGE::Math::normalMatrix(bm);
        auto bt = Pipeline::projectObject(ball, bm, vp, bnrm, W, H);

        int rc = std::min(255, id * 5);   // 红色随 id 递增
        for (auto &t : bt) {
            t.v[0].color = t.v[1].color = t.v[2].color = Color32{rc, 0, 0, 255};
            rz.drawTriangleWireframe(t.v[0], t.v[1], t.v[2]);  // 线框绘制
        }
        id++;
    }
}
```

### 5.9 超采样抗锯齿（SSAA）

&emsp;&emsp;SSAA（Super-Sampling Anti-Aliasing）在更高分辨率下渲染，再下采样到目标分辨率，通过**超采样**消除锯齿。

#### 5.9.1 SSAA 原理

&emsp;&emsp;锯齿（Aliasing）发生在采样率不足时。SSAA 通过提高采样率来减少锯齿：

- **2x SSAA**：先以更高分辨率渲染，再按 2×2 邻域盒滤波降采样到目标分辨率
- **4x SSAA**：更高倍率的超采样 + 盒滤波

&emsp;&emsp;注意：SSAA 与**动态渲染分辨率**（`g_renderW/g_renderH`）是两回事。动态渲染分辨率是按性能需求**降低**内部渲染分辨率再放大上屏（帧率优化手段），不会消除锯齿；SSAA 则是**固定地**在更高分辨率渲染后降采样（抗锯齿手段），两者方向相反。

#### 5.9.2 盒滤波下采样

&emsp;&emsp;下采样使用**盒滤波**（Box Filter），对 2×2 区域取平均。当前引擎的 `MSAA` 场景以原生分辨率渲染容器贴图立方体，仅实现**灰度化**档（ImGui "Enable MSSA" 复选框）；**未实现完整的 SSAA 渲染路径**——"Enable FrameBuffer MSSA"（4x 超采样）复选框已声明但尚未接入渲染路径。

&emsp;&emsp;若要实现 SSAA，需要将内部渲染目标设为更高分辨率（例如 1600×1200），渲染后再用盒滤波降采样到目标分辨率（800×600）。目前这一流程未在引擎中落地；`g_renderW/g_renderH` 是动态渲染分辨率（性能优化，见 5.9.1），并非 SSAA 的实现载体。

```cpp
// 灰度化（图 27 场景的 "Enable MSSA" 档）
uint32_t c = fb.colorData()[y * 800 + x];
int g = (int)(0.2126 * ((c >> 16) & 0xFF)
            + 0.7152 * ((c >> 8) & 0xFF)
            + 0.0722 * (c & 0xFF));
fb.setPixelOverlay(x, y, 0xFF000000u | (g << 16) | (g << 8) | g);
```

#### 5.9.3 SSAA 的代价

- **N 倍内存**：需要更大的帧缓冲
- **N 倍计算**：渲染更多像素
- **带宽消耗**：读写更多数据

&emsp;&emsp;SSAA 是最简单的抗锯齿方法，效果也最好，但性能代价最高。实际项目中常用更高效的 FXAA 或 TAA。

### 6.1 Shadow Mapping

&emsp;&emsp;阴影映射（Shadow Mapping）通过两遍渲染实现阴影：

1. **深度 Pass**：从光源视角渲染场景，只记录深度值到阴影贴图
2. **渲染 Pass**：从相机视角渲染，将片段变换到光源空间，比较深度值判断是否在阴影中

#### 6.1.1 方向光阴影

&emsp;&emsp;方向光使用**正交投影**生成阴影贴图（引擎在 `Shadow.hpp` 中提供 `directionalLightVP`，当前无场景使用）：

```cpp
// 光源 VP 矩阵（正交投影，适用于方向光）
auto lightVP = directionalLightVP(dir, center, extent);  // 正交 ±extent，near 0.1 far 4*extent

// 渲染 Pass 中采样阴影贴图
Vector3D lightSpacePos = (lightVP * worldPos).xyz();
float shadowDepth = shadowMap.sample(lightSpacePos.x, lightSpacePos.y);
bool inShadow = (currentDepth - bias > shadowDepth);
```

&emsp;&emsp;**注意**：当前 `ShadowMap` 场景（图 30）实际使用的是**聚光灯 + 透视投影**的阴影贴图（`pointLightVP(lightPos, {0,-1.5,0}, fovY=π/2, aspect=1, near=0.5, far=60)`，阴影图 256×256），而非方向光正交投影。`directionalLightVP` 仅在 `Shadow.hpp` 中定义备查。

#### 6.1.2 点光源立方体阴影

&emsp;&emsp;点光源需要**六个方向**的阴影贴图，形成立方体贴图：

```cpp
// 6 个面的 VP 矩阵（第二参数是面索引 0-5，far 固定 100.0）
for (int i = 0; i < 6; i++) {
    auto faceVP = cubeFaceVP(lightPos, i);   // 90° FOV 透视投影
    renderDepthPass(faceVP, cubeShadow.faces[i]);
}

// 采样时根据方向选择面
int face = cubeFaceIndex(lightDir);          // 0-5: ±X,±Y,±Z
float shadowDepth = cubeShadow.faces[face].sample(u, v);
```

#### 6.1.3 PCF 软阴影

&emsp;&emsp;PCF（Percentage Closer Filtering）对阴影贴图进行邻域采样，产生柔和的阴影边缘：

```cpp
// 引擎实现：PCF 邻域统计遮挡比例，shadowFactor = 1 - 遮挡比
int occluded = 0, total = 0;
for (int oy = -pcfRadius; oy <= pcfRadius; oy++) {
    for (int ox = -pcfRadius; ox <= pcfRadius; ox++) {
        // 越界钳制到阴影图边界
        auto sx2 = clamp((int)sx + ox, 0, (int)smW - 1);
        auto sy2 = clamp((int)sy + oy, 0, (int)smH - 1);
        float dLight = depthData[sy2 * smW + sx2];
        if (zMain01 > dLight + bias) occluded++;   // 在阴影中
        total++;
    }
}
shadowFactor = 1.0 - (double)occluded / total;   // 0=全阴影, 1=全亮
```

### 6.2 法线贴图

&emsp;&emsp;法线贴图（Normal Mapping）用纹理存储表面细节法线，在不增加几何复杂度的情况下增强凹凸感。

&emsp;&emsp;引擎的 `ShadingContext` 直接传入**切线基**（`tangentU`/`tangentV`），无需在管线中计算 `B = N×T`。法线贴图采样的颜色 `[0,1]` 解码到 `[-1,1]`，再在像素着色中按 $N' = T \cdot n_x + B \cdot n_y + N \cdot n_z$ 组合成世界空间法线：

```cpp
// NormalMap 场景：墙面朝相机 N=(0,0,-1)，T=(1,0,0)，B=(0,1,0)
ShadingContext ctx{&rig, camPos};
ctx.normalTex = &normal;                          // 法线贴图
ctx.tangentU = Vector3D{1, 0, 0};
ctx.tangentV = Vector3D{0, 1, 0};

// 像素着色中（Rasterizer）：
// 1. 采样法线贴图并解码 [0,1] → [-1,1]
Vector3D nMap{tex.r * 2 - 1, tex.g * 2 - 1, tex.b * 2 - 1};
// 2. 切线基组合出世界空间法线
Vector3D N = normalize(
    tangentU * nMap.x + tangentV * nMap.y + worldNormal * nMap.z);
```

### 6.3 视差贴图

&emsp;&emsp;视差贴图（Parallax Mapping）通过纹理坐标偏移模拟表面深度细节：

```cpp
// Steep Parallax Mapping（8 层），与引擎实现一致
if (shading->heightTex && shading->parallaxScale > 0.0) {
    Vector3D V = shading->viewPos - P;          // 从表面指向相机
    if (V.length() > 1e-9) {
        V = V.normalize();                      // 归一化为单位视线方向
        double tz = V.dot(N);                   // 视线在切线基 z 分量（法线分量）
        if (std::abs(tz) > 1e-6) {
            // 视线在切面的投影 P = viewDir.xy/viewDir.z·scale，采样点沿 -P
            // 方向（远离相机）逐层偏移，步长 P/steps
            double px = V.dot(T) / tz * parallaxScale;
            double py = V.dot(B) / tz * parallaxScale;
            const int steps = 8;
            double layerD = 1.0 / steps;
            double cu = 0.0, cv = 0.0;          // 已偏移的 UV（相对原始采样点）
            double curDepth = 0.0;              // 当前层深度（0 → 1 递增）
            for (int i = 0; i < steps; i++) {
                float h = heightTex.sample(u + cu, v + cv).b / 255.0f;  // 采样高度
                if (curDepth >= h) break;       // 视线已穿入高度场，停止
                cu -= px / steps;               // 每层远离相机偏移
                cv -= py / steps;
                curDepth += layerD;
            }
            u += cu; v += cv;                   // 偏移后的 UV 用于后续采样
        }
    }
}
```

&emsp;&emsp;步进语义：高度图 $h$（0~1）表示表面高度（1 为凸起最高点，0 为凹陷底面）。视线从表面指向相机，其在切面的投影为 $P=(V\cdot T, V\cdot B)/tz \cdot scale$。采样点从原始 UV 出发，**沿 $-P$ 方向（远离相机）** 逐层推进 `P/steps`，层深度 `curDepth` 从 0 递增到 1；当当前层深度首次 $\ge$ 该偏移处的高度 $h$ 时，说明视线已穿过表面起伏，取该偏移后的 UV 采样颜色，从而产生"表面凹凸使采样点偏移"的视差效果。凸起越高（$h$ 越大）、视线越倾斜，偏移量越大。注意：偏移方向与视线在切面的投影方向**相反**（远离相机），这是视差贴图的标准约定（参考 GraphicsAPILearn 的 `ParallaxMapping`/`ParallaxMappingSteep`）。

### 6.4 HDR 与色调映射

```cpp
// Reinhard 色调映射
ColorFlt ReinhardToneMap(ColorFlt hdr) {
    return hdr / (hdr + ColorFlt{1.0f});
}

// ACES 色调映射（更电影感）
ColorFlt ACESToneMap(ColorFlt hdr) {
    float a = 2.51f, b = 0.03f, c = 2.43f, d = 0.59f, e = 0.14f;
    return saturate((hdr * (a * hdr + b)) / (hdr * (c * hdr + d) + e));
}

// 曝光控制（引擎 HDR 场景：1-exp 曝光 ×6.0 系数后接 gamma 1/2.2）
// 4096 项曝光+gamma LUT 替代逐像素 exp/pow（仅曝光变化时重建）
double lut[i] = pow(clamp(1 - exp(-(i/4095.0) * 6.0 * exposure), 0, 1),
                    1.0 / 2.2) * 255.0 + 0.5;
```

### 6.5 Bloom

&emsp;&emsp;Bloom 效果让明亮区域"溢出"光芒，模拟真实摄像机的光晕：

1. **亮度提取**：提取超过阈值的高亮区域
2. **高斯模糊**：对高亮区域进行可分离高斯模糊
3. **加法混合**：将模糊结果叠加到原始图像

```cpp
// 亮度提取（引擎用乘性软阈值：亮度越接近阈值越弱，非硬截断）
// 半分辨率(400×300)下提取，降低后续模糊开销
for (int y = 0; y < 300; y++)
    for (int x = 0; x < 400; x++) {
        uint32_t c = srcPx[(y*2) * W + x*2];
        int lumR = (c >> 16) & 0xFF;         // 源 R 通道
        int lumG = (c >> 8) & 0xFF;          // 源 G 通道
        int lumB = c & 0xFF;                 // 源 B 通道
        double lum = 0.2126 * lumR + 0.7152 * lumG + 0.0722 * lumB;
        double thr = expose * 255.0;
        if (lum > thr) {
            double k = (lum - thr) / max(1e-3, lum);  // 软阈值系数
            bright.setPixelOverlay(x, y, 0xFF000000u
                | ((uint32_t)(lumR * k) << 16)
                | ((uint32_t)(lumG * k) << 8)
                | (uint32_t)(lumB * k));
        }
    }

// 可分离高斯模糊（原地修改 FrameBuffer，水平+垂直两遍）
void GaussianBlur(FrameBuffer &fb, int radius);

// 加法混合（饱和相加，无强度缩放）
void AdditiveBlend(FrameBuffer &dst, const FrameBuffer &bright);
```

### 6.6 延迟着色

&emsp;&emsp;延迟着色（Deferred Shading）将几何信息存储在 G-Buffer 中，光照计算推迟到屏幕空间：

1. **G-Buffer Pass**：渲染场景，存储法线、颜色等到多张帧缓冲
2. **光照 Pass**：逐像素读取 G-Buffer，计算光照

&emsp;&emsp;引擎的 `Defer` 场景使用**法线 + 反照率两张 G-Buffer**（法线编码为 $(n \cdot 0.5 + 0.5) \times 255$），**不存储世界空间位置**——光照 pass 用固定光源位置与 N·L 估算，不重建世界坐标。

> **注意**：这是**简化教学版**的延迟渲染。真实延迟渲染会额外存储一张位置（或由深度重建）G-Buffer，以支持正确的点光衰减、阴影、视差等需要世界坐标的效果。引擎的 G-Buffer 仅两张，无法正确计算点光距离衰减，只演示了"先几何后光照"的流程划分。

```cpp
// G-Buffer 结构（引擎：albedo + normal 两张，无 position）
struct GBuffer {
    FrameBuffer normal;    // 法线编码 (n*0.5+0.5)*255
    FrameBuffer albedo;    // 漫反射颜色
};

// 光照 Pass：逐像素读取法线与反照率，用光源位置估算
for (each pixel) {
    Vector3D norm = decodeNormal(gBuffer.normal);
    ColorFlt albedo = gBuffer.albedo;
    // 逐光源计算（用 N·L 估算，不重建世界坐标）
    ColorFlt result = shade(norm, albedo, lights);
}
```

### 6.7 SSAO

&emsp;&emsp;环境光遮蔽（Screen-Space Ambient Occlusion）在屏幕空间估算角落和缝隙的遮蔽。

&emsp;&emsp;引擎的 `SSAO` 场景采用**深度对比接触阴影**近似：对每个像素检查 3×3 邻域，若某邻居深度显著更深（`dn > d + 0.008`），则该像素被遮蔽，叠加遮蔽量后压暗颜色：

```cpp
// 引擎实现：3×3 邻域深度对比（非半球采样）
for (int y = 1; y + 1 < h; y++)
    for (int x = 1; x + 1 < w; x++) {
        float d = dep[y * w + x];
        if (d <= 0.0f || d >= 1.0f) continue;   // 跳过天空/未写入
        float occ = 0.0f;
        for (int oy = -1; oy <= 1; oy++)
            for (int ox = -1; ox <= 1; ox++) {
                float dn = dep[(y + oy) * w + (x + ox)];
                if (dn > d + 0.008f) occ += 0.14f;   // 邻居更深 → 遮蔽
            }
        occ = std::min(occ, 0.65f);                 // 上限
        if (occ <= 0.01f) continue;
        uint32_t c = src[y * w + x];                // 压暗颜色
        setPixelOverlay(x, y,
            ((c>>16)&0xFF)*(1-occ) | ((c>>8)&0xFF)*(1-occ) | (c&0xFF)*(1-occ));
    }
```

## 7 PBR 与光线追踪

&emsp;&emsp;本章介绍引擎的物理渲染（PBR）与光线追踪两条渲染路径。需要说明的是：**Cook-Torrance PBR / IBL 实现于光栅化路径**（`Light::pbrShade` + `Rasterizer` + `ImageLoader` 预计算）；**光线追踪路径**（`RayTracer`）使用 Blinn-Phong + Lambert + 环境光着色，不包含 PBR/IBL。

### 7.1 物理渲染（PBR）

&emsp;&emsp;PBR（Physically Based Rendering）基于物理原理，使用 **Cook-Torrance BRDF** 模型：

$$f_r = k_d \cdot \frac{f_{Lambert}}{\pi} + k_s \cdot \frac{D \cdot F \cdot G}{4 \cdot (n \cdot \omega_o) \cdot (n \cdot \omega_i)}$$

#### 7.1.1 法线分布函数（D）

&emsp;&emsp;GGX 分布函数描述微表面法线的统计分布：

$$D_{GGX}(h) = \frac{\alpha^2}{\pi \cdot ((n \cdot h)^2 \cdot (\alpha^2 - 1) + 1)^2}$$

#### 7.1.2 几何遮蔽函数（G）

&emsp;&emsp;Smith 方法估算微表面自遮挡：

$$G = G_{SchlickGGX}(n, v, k) \cdot G_{SchlickGGX}(n, l, k)$$

#### 7.1.3 菲涅尔函数（F）

&emsp;&emsp;Schlick 近似估算菲涅尔效应：

$$F = F_0 + (1 - F_0) \cdot (1 - \cos\theta)^5$$

#### 7.1.4 IBL 环境光照

&emsp;&emsp;基于图像的光照（IBL）使用预计算的环境贴图。引擎在光栅化 PBR 路径中实现：

- **漫反射 IBL**：`ComputeIrradiance` 余弦加权半球积分预计算辐照度图（64×32 equirect），着色时 `SampleEquirect(iblEquirect, N, 0.35f)` 采样
- **高光 IBL**：`ComputePrefiltered` 生成 3 级粗糙度模糊的 equirect mip，按 `roughness*3` 选级，`SampleEquirectClamped` 采样
- **BRDF**：用 **Karis 解析近似** `EnvBRDFApprox(NoV, rough, f0)`（返回 scale/bias）替代 BRDF LUT 贴图

```cpp
// 漫反射 IBL（辐照度图）
auto irr = SGE::Render::SampleEquirect(*shading->iblEquirect, N, 0.35f);
br = br + irr.r * kd * (albedo.r / 255.0) + specR;   // kd 系数叠加

// 高光 IBL（预滤波 mip，3 级，rough 0.15/0.50/0.85）
int lv = min(mips.size() - 1, (int)(rough * 3.0));
auto pc = SGE::Render::SampleEquirectClamped(mips[lv], R, 1.0f);

// Karis Split-Sum 解析 BRDF（替代 BRDF LUT 贴图）
double f0 = 0.04 + 0.96 * metallic;
double fr = f0 + (max(f0, 1.0 - rough) - f0) * pow(1.0 - NoV, 5.0);  // Schlick
auto sb = SGE::Render::EnvBRDFApprox(NoV, rough, f0);   // x=scale, y=bias
specR = pc.r * fr * sb.x + sb.y;   // bias 逐通道相加
```

&emsp;&emsp;两点说明：
- **F0 简化**：`f0 = 0.04 + 0.96 * metallic` 对非金属（F0≈0.04）成立，但对金属忽略了**反照率颜色**（金属的 F0 应为 RGB 反照率，才能呈现铜、金等彩色金属）。引擎 PBR 光栅化路径（`pbrShade` 的点光/方向光分支）已正确处理彩色金属，仅 IBL 高光分支用灰度近似，视觉上对非金属无影响。
- **Fresnel 修正**：标准 Schlick 近似为 $F = F_0 + (1 - F_0)(1-\cos\theta)^5$。这里用 $\max(F_0, 1-\text{rough})$ 替代 1，使粗糙表面在高角度时高光更快衰减（粗表面 F 向 F90 收敛的工程近似），并非教科书原始公式，属引擎实现细节。

### 7.2 光线追踪

&emsp;&emsp;光线追踪从像素发射光线，与场景求交，递归计算光照和反射/折射。

#### 7.2.1 光线与球体求交

&emsp;&emsp;光线方程：$P(t) = O + t \cdot D$

&emsp;&emsp;球体方程：$|P - C|^2 = r^2$

&emsp;&emsp;代入得二次方程：

$$a \cdot t^2 + b \cdot t + c = 0$$

$$t = \frac{-b \pm \sqrt{b^2 - 4ac}}{2a}$$

```cpp
// 实际签名：dir 假定已归一化，采用简化判别式 b²-c（等价于 a=1 时 -b±√disc）
bool raySphereIntersect(const RaySphere &s,
                        const Vector3D &origin, const Vector3D &dir,
                        double &outDist) {
    Vector3D oc = origin - s.center;
    double b = oc.dot(dir);
    double c = oc.dot(oc) - s.radius * s.radius;
    double disc = b * b - c;
    if (disc < 0) return false;
    double sq = std::sqrt(disc);
    double t = -b - sq;          // 近交点
    if (t < kEps) {              // 若在射线起点后，尝试远交点
        t = -b + sq;
        if (t < kEps) return false;
    }
    outDist = t;
    return true;
}
```

#### 7.2.2 光线与三角形求交（Möller-Trumbore）

&emsp;&emsp;Möller-Trumbore 算法高效计算光线与三角形的交点：

```cpp
// 实际签名：只输出距离 outDist，不输出重心坐标 u/v
bool rayTriangleIntersect(const RayTriangle &tri,
                          const Vector3D &origin, const Vector3D &dir,
                          double &outDist) {
    Vector3D e1 = tri.b - tri.a, e2 = tri.c - tri.a;
    Vector3D p = dir.mul(e2);              // dir × e2（mul 即叉积）
    double det = e1.dot(p);
    if (std::abs(det) < kEps) return false;   // 平行或退化
    double invDet = 1.0 / det;
    Vector3D tv = origin - tri.a;
    double u = tv.dot(p) * invDet;
    if (u < -kEps || u > 1.0 + kEps) return false;

    Vector3D q = tv.mul(e1);               // tv × e1
    double v = dir.dot(q) * invDet;
    if (v < -kEps || u + v > 1.0 + kEps) return false;

    double t = e2.dot(q) * invDet;
    if (t < kEps) return false;
    outDist = t;
    return true;
}
```

#### 7.2.3 反射与折射

&emsp;&emsp;反射向量：$R = I - 2 \cdot (I \cdot N) \cdot N$

&emsp;&emsp;折射向量（Snell 定律，$\eta$ 为相对折射率 $\frac{\eta_i}{\eta_t}$）：

$$T = \eta \cdot I + (\eta \cdot \cos\theta_i - \cos\theta_t) \cdot N$$

&emsp;&emsp;引擎用 **Schlick 菲涅尔**决定反射/折射权重。与教科书"随机按概率分支"不同，引擎采用**确定性混合**：全内反射或菲涅尔系数 > 0.5 时只追踪反射射线，否则追踪折射射线并按其权重混合（避免光线分裂指数级增长）：

```cpp
// 折射分支（hit.refractivity > 0 时进入）
const double fresnel = SchlickFresnel(cosI, etaRatio);  // etaRatio 为相对折射率
Vector3D rf;
bool tir = !Refract(D, hit.normal, eta, rf);   // 全内反射时 Refract 返回 false

if (tir || fresnel > 0.5) {
    // 只追踪反射（fresnel 高时折射贡献可忽略，且避免分裂）
    auto R = reflect(D, hit.normal);
    uint32_t reflColor = traceAndShade(scene, hit.point + R*eps, R, depth+1);
    local = MixChannels(local, reflColor, fresnel);
} else {
    // 追踪折射，按 折射率 × (1-fresnel) 混合
    uint32_t refrColor = traceAndShade(scene, hit.point + rf*eps, rf, depth+1);
    local = MixChannels(local, refrColor, rr * (1.0 - fresnel));
}
```

#### 7.2.4 光锥体积效果

&emsp;&emsp;光锥效果通过 ray-marching 沿视线方向采样体积密度（引擎内联在 `RayTracer::render`，8 步）：

```cpp
// 8 步 ray-marching：步长取 min(命中距离, 锥范围)/8
if (scene.cone.enabled) {
    double coneAccum = 0.0;
    constexpr int kSteps = 8;
    double maxT = hit.hit ? std::min(hit.dist, scene.cone.range) : scene.cone.range;
    double stepLen = maxT / kSteps;
    for (int st = 1; st <= kSteps; st++) {
        Vector3D sp = camera.position + dir * (st * stepLen);
        Vector3D rel = sp - scene.cone.position;
        double dist = rel.length();
        if (dist < 0.1 || dist > scene.cone.range) continue;
        double cosA = normalize(rel).dot(normalize(scene.cone.direction));
        if (cosA < scene.cone.cutoffCos) continue;      // 锥外
        double edgeFade = (cosA - scene.cone.cutoffCos)
                        / max(1e-4, 1.0 - scene.cone.cutoffCos);  // 边缘衰减
        double distFade = 1.0 - (dist / scene.cone.range);        // 距离衰减
        coneAccum += edgeFade * distFade * distFade * stepLen;    // 密度累积
    }
    coneAccum = std::min(coneAccum * 0.04 * scene.cone.intensity, 1.0);
    // 暖色 (1.0, 0.93, 0.85) 混入最终颜色
}
```

## 8 并行优化

### 8.1 Tile 分块并行

&emsp;&emsp;SoftGameEngine 实现了基于 **64×64 tile** 的多线程并行光栅化：

```cpp
// 实际 API：输入已裁剪的 ScreenTriangle 列表，按 AABB 分桶到相交 tile
void drawTextured(const std::vector<Pipeline::ScreenTriangle> &tris,
                  const Texture &tex, const ShadingContext *ctx,
                  TextureFilter filter = TextureFilter::Bilinear,
                  TextureWrap wrap = TextureWrap::Repeat,
                  unsigned threads = std::thread::hardware_concurrency()) {
    const std::size_t W = m_fb.width(), H = m_fb.height();
    constexpr std::size_t kTile = 64;                 // 64×64 tile
    const std::size_t cols = (W + kTile - 1) / kTile;
    const std::size_t rows = (H + kTile - 1) / kTile;
    const std::size_t tileCount = cols * rows;

    // 1. 按三角形 AABB 计算覆盖的 tile 范围，把【索引】推入相交的所有桶
    std::vector<std::vector<std::uint32_t>> buckets(tileCount);
    for (uint32_t i = 0; i < tris.size(); i++) {
        const auto &t = tris[i];
        double minX = std::min({t.v[0].x, t.v[1].x, t.v[2].x});
        double maxX = std::max({t.v[0].x, t.v[1].x, t.v[2].x});
        double minY = std::min({t.v[0].y, t.v[1].y, t.v[2].y});
        double maxY = std::max({t.v[0].y, t.v[1].y, t.v[2].y});
        if (maxX < 0 || maxY < 0) continue;
        if (minX >= (double)W || minY >= (double)H) continue;
        size_t c0 = floor(max(0.0, minX)) / kTile;
        size_t c1 = min(cols - 1, floor(max(0.0, maxX)) / kTile);
        size_t r0 = floor(max(0.0, minY)) / kTile;
        size_t r1 = min(rows - 1, floor(max(0.0, maxY)) / kTile);
        for (size_t r = r0; r <= r1; r++)
            for (size_t c = c0; c <= c1; c++)
                buckets[r * cols + c].push_back(i);
    }

    // 2. 固定 threads 个工作线程，步长式分块（worker(0) 主线程也参与）
    if (threads == 0) threads = 1;
    if (threads > tileCount) threads = (unsigned)tileCount;
    auto worker = [&](unsigned id) {
        Rasterizer rz{m_fb};
        for (size_t t = id; t < tileCount; t += threads) {
            ScreenRect clip{};
            clip.x0 = (int)((t % cols) * kTile);
            clip.y0 = (int)((t / cols) * kTile);
            clip.x1 = (int)std::min(W, ((t % cols) + 1) * kTile) - 1;
            clip.y1 = (int)std::min(H, ((t / cols) + 1) * kTile) - 1;
            for (auto idx : buckets[t]) {
                const auto &tri = tris[idx];
                rz.drawTriangleTextured(tri.v[0], tri.v[1], tri.v[2],
                                        tex, ctx, filter, wrap, &clip);
            }
        }
    };
    std::vector<std::thread> pool;
    pool.reserve(threads - 1);
    for (unsigned i = 1; i < threads; i++) pool.emplace_back(worker, i);
    worker(0);
    for (auto &th : pool) th.join();
}
```

&emsp;&emsp;**正确性论证**：每个像素的三角形处理序列与串行一致（每个三角形的所有覆盖像素只在其 AABB 相交的 tile 中处理，且该 tile 由唯一线程负责），因此结果**逐位等价**于串行渲染。
