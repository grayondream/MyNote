# 自旋锁

## 1 简介
&emsp;&emsp;自旋锁是一种典型的无锁算法，在任何时刻，它都最多只能有一个保持者。当有一个线程试图获得一个已经被占用的锁时，该线程就会一直进行循环等待，直到该锁被释放。自旋锁的优点是不会使线程状态发生切换，一直处于用户态，即线程一直都是active的；缺点是如果一直获取不到锁，那线程就一直处于循环等待中，白白浪费CPU资源。自旋锁在某些场景下非常有效，尤其是临界区较小且持有时间短的情况下。然而，在高竞争或临界区较长的情况下，使用自旋锁可能导致性能下降，因此需谨慎选择。

## 2 不同自旋锁的实现
&emsp;&emsp;自旋锁的实现有多种方式，包括：
- 比较并交换（CAS）：CAS是一种原子操作，它可以比较一个内存位置的值与一个期望值是否相等，如果相等则将该位置的值更新为一个新值。
- 测试并设置（TAS）：TAS是一种原子操作，它可以测试一个内存位置的值是否为0，如果为0则将该位置的值设置为1。
- 互斥量：互斥量是一种同步原语，它可以确保同一时刻只有一个线程可以访问共享资源。
- 信号量：信号量是一种同步原语，它可以确保同一时刻只有一定数量的线程可以访问共享资源。
- 屏障：屏障是一种同步原语，它可以确保同一时刻只有一定数量的线程可以访问共享资源。

### 2.1 TASLock
&emsp;&emsp;TASLock的实现比较简单，只需要一个bool类型的变量flag来表示锁的状态，当flag为false时表示锁可用，当flag为true时表示锁不可用。当一个线程试图获取锁时，它会不断地检查flag的值，如果flag为false，则将flag设置为true，表示锁被占用，否则自旋等待。当一个线程释放锁时，它会将flag设置为false，表示锁可用。TASLock的实现如下所示：
```cpp
class TASLock {
public:
    TASLock() : flag(false) {}

    void lock() {
        // 自旋等待直到能够获取锁
        while (flag.exchange(true, std::memory_order_acquire)) {
            // 自旋，直到锁被释放
        }
    }

    void unlock() {
        // 释放锁
        flag.store(false, std::memory_order_release);
    }

private:
    std::atomic<bool> flag; // 锁的标志
};
```

&emsp;&emsp;TAS实现简单，但是由于它是不断尝试TEST_AND_SET，当多个线程在不同的 CPU 核心上竞争同一个 TAS 锁时，所有线程都会频繁地读取和写入锁的状态。这会导致缓存行的频繁失效，因为每次一个线程更新锁的状态时，其他线程的缓存中相应的缓存行会失效，从而引发更高的内存访问延迟。这不仅增加了内存带宽的消耗，还可能导致内存访问争用，进而影响到系统的整体性能。在高竞争环境下，线程自旋等待锁的状态，频繁地访问同一内存地址，可能导致内存访问延迟显著增加。每次缓存失效都需要访问主内存，从而增加了获取锁的时间。

### 2.2 TTASLock
&emsp;&emsp;TTASLock的实现与TASLock类似，只是在获取锁时先测试锁的状态，如果锁已经被占用，则自旋等待，否则尝试获取锁。TTASLock的实现如下所示：
```cpp
class TTASLock {
public:
    TTASLock() : flag(false) {}

    void lock() {
        // 自旋等待，直到锁未被占用
        while (true) {
            // 先测试锁的状态
            while (flag.load(std::memory_order_acquire)) {
                // 自旋等待，直到锁被释放
            }
            // 尝试获取锁
            if (!flag.exchange(true, std::memory_order_acquire)) {
                // 成功获取锁
                break;
            }
        }
    }

    void unlock() {
        // 释放锁
        flag.store(false, std::memory_order_release);
    }

private:
    std::atomic<bool> flag; // 锁的标志
};
```

&emsp;&emsp;TTAS 首先测试锁的状态，而不是立即尝试获取锁。只有在确认锁未被占用时，才会进行写操作（即设置 flag），这减少了对共享内存的写入操作，降低了总线争用的频率。由于 TTAS 在尝试获取锁之前先检查锁的状态，只有在锁未被占用时才会进行 CAS 操作，这可以减少其他线程在尝试获取锁时导致的缓存失效，从而提高性能。在多线程竞争不激烈的情况下，TTAS 锁可以更高效地降低自旋带来的 CPU 资源浪费，尤其是在锁的持有时间短的情况下。尽管 TTAS 减少了总线争用，但它仍然是自旋锁。在线程自旋等待锁时，CPU 资源仍然被消耗，特别是在高竞争情况下，可能导致性能下降。TTAS 的实现依赖于原子操作（如 CAS），在某些硬件架构上，这些操作可能仍然导致较高的延迟，尤其是在较高的竞争情况下。

### 2.3 指数退避锁
&emsp;&emsp;指数退避算法是一种在并发系统中，当多个线程争用同一个锁时，用于减少资源竞争的策略。它通过在每次尝试获取锁失败后，等待一段时间再重试，并且等待的时间长度逐渐增加，从而避免系统频繁尝试而导致过载、资源竞争或者死锁。
1. 首次尝试： 线程尝试获取锁。
2. 失败后等待： 如果获取锁失败，线程会等待一段时间。
3. 指数增加： 等待时间会以指数方式增加，例如，第一次等待1毫秒，第二次等待2毫秒，第三次等待4毫秒，以此类推。
4. 重试： 等待时间结束后，线程再次尝试获取锁。
5. 达到上限： 为了防止等待时间过长，通常会设置一个最大等待时间。当等待时间达到上限时，就不再增加。
6. 加入随机抖动： 为了避免多个请求同时重试导致系统再次过载，可以在指数退避的基础上，加入一些随机性，使得重试的时间并不是固定的，而是随机的。

```cpp
class ExponentialBackoffTTASLock {
private:
    std::atomic_flag lock_flag = ATOMIC_FLAG_INIT;
    unsigned int max_delay_ms;
    std::default_random_engine generator;
    std::uniform_int_distribution<unsigned int> distribution;

public:
    ExponentialBackoffTTASLock(unsigned int max_delay = 100) : max_delay_ms(max_delay), distribution(0, max_delay) {}

    void lock() {
        unsigned int delay = 1;
        while (true) {
            // Test: 自旋等待锁释放
            while (lock_flag.test_and_set(std::memory_order_acquire)) {
                // 锁被占用，继续自旋
            }

            // Test-and-Set: 尝试获取锁
            if (!lock_flag.test_and_set(std::memory_order_acquire)) {
                // 成功获取锁
                return;
            } else {
                // 获取锁失败，进行指数退避
                std::this_thread::sleep_for(std::chrono::milliseconds(delay));
                delay = std::min(delay * 2, max_delay_ms); // 指数增长，但限制最大值
            }
        }
    }

    void unlock() {
        lock_flag.clear(std::memory_order_release);
    }
};
```

&emsp;&emsp;指数后退的随机抖动可以减少多个线程同时重试的情况，从而减少系统的负载。这有助于避免在高竞争情况下，多个线程同时重试获取锁，从而导致系统过载。但是，指数后退的随机抖动也可能导致某些线程的重试时间过长，从而降低系统的性能。因此，在使用指数后退时，需要根据实际情况进行调整，以达到最佳的性能和资源利用率。

### 2.4 队列锁
#### 2.4.1 数组队列锁
&emsp;&emsp;队列锁是一种基于队列的锁实现，它允许多个线程同时尝试获取锁，但是只有一个线程能够成功获取锁。队列锁的实现如下所示：
```cpp
class QueueLock {
private:
    std::atomic<int> tail;   // 队尾指针
    std::atomic<int> head;   // 队头指针
    std::vector<std::atomic<bool>> flag; // 每个线程对应的标志位
    int size;

public:
    QueueLock(int max_threads) : tail(0), head(0), size(max_threads) {
        flag.resize(max_threads);
        for (int i = 0; i < max_threads; ++i) {
            flag[i].store(false, std::memory_order_relaxed); // 初始状态为 false
        }
        flag[0].store(true, std::memory_order_relaxed); // 第一个线程可以立即获取锁
    }

    void lock(int thread_id) {
        int ticket = tail.fetch_add(1, std::memory_order_acquire); // 获取排队号码
        while (!flag[ticket % size].load(std::memory_order_acquire)) {
            // 自旋等待轮到自己
            std::this_thread::yield(); // 可以选择让出 CPU
        }
    }

    void unlock(int thread_id) {
        int next = (head.load(std::memory_order_relaxed) + 1) % size;
        flag[next].store(true, std::memory_order_release); // 允许下一个线程获取锁
        head.fetch_add(1, std::memory_order_release); // 移动队头指针
        flag[head.load(std::memory_order_relaxed) % size].store(false, std::memory_order_release); //将当前线程的flag设置为false
    }
};
```

&emsp;&emsp;队列锁通过维护一个请求锁的线程队列，保证了线程按照先来后到的顺序获取锁，解决了传统锁可能导致的线程饥饿问题，确保了公平性。但队列锁需要在初始化时确定最大线程数，限制了其扩展性，并且自旋等待的机制在锁竞争激烈时会浪费 CPU 资源。

#### 2.4.2 CLH队列锁
```cpp
class CLH_Lock {
private:
    struct QNode {
        std::atomic<bool> locked;
    };

    std::atomic<QNode*> tail;
    thread_local QNode my_node;
    thread_local QNode my_pred;

public:
    CLH_Lock() : tail(nullptr) {}

    void lock() {
        my_node.locked.store(true, std::memory_order_release); // 我要开始排队了
        QNode* pred = tail.exchange(&my_node, std::memory_order_acquire); // 将当前节点加入队尾，并获取前驱节点
        my_pred = pred ? pred : &my_node; // 如果队列为空，则前驱节点为自己
        while (my_pred->locked.load(std::memory_order_acquire)) {
            // 自旋等待前驱节点释放锁
            std::this_thread::yield(); // 可以选择让出 CPU
        }
    }

    void unlock() {
        my_node.locked.store(false, std::memory_order_release); // 释放锁，允许后继节点获取锁
        tail.compare_exchange_strong(&my_node, nullptr);
    }
};
```

&emsp;&emsp;CLH 队列锁通过链表结构维护等待锁的线程队列，解决了传统锁的公平性问题以及普通队列锁需要预先确定最大线程数的限制，实现了更好的可扩展性。然而，CLH 锁仍然存在自旋等待的问题，这会导致 CPU 资源的浪费，并且每个线程都需要额外的内存来存储队列节点。

#### 2.4.3 MCS锁
&emsp;&emsp; MCS锁也是一种基于链表的公平锁，它与 CLH 锁类似，但 MCS 锁的节点直接指向后继节点，而不是前驱节点，这使得释放锁的操作更加简单高效。

```cpp
class MCSLock {
private:
    struct QNode {
        std::atomic<QNode*> next;
        std::atomic<bool> locked;

        QNode() : next(nullptr), locked(false) {}
    };

    std::atomic<QNode*> tail;
    thread_local QNode my_node;

public:
    MCSLock() : tail(nullptr) {}

    void lock() {
        QNode* old_tail = tail.exchange(&my_node, std::memory_order_acquire);
        if (old_tail != nullptr) {
            my_node.locked.store(true, std::memory_order_release);
            old_tail->next.store(&my_node, std::memory_order_release);
            while (my_node.locked.load(std::memory_order_acquire)) {
                std::this_thread::yield(); // 让出CPU
            }
        }
    }

    void unlock() {
        if (my_node.next.load(std::memory_order_acquire) == nullptr) {
            QNode* expected = &my_node;
            if (tail.compare_exchange_strong(expected, nullptr, std::memory_order_release, std::memory_order_relaxed)) {
                return;
            }
            while (my_node.next.load(std::memory_order_acquire) == nullptr) {
                std::this_thread::yield();
            }
        }
        my_node.next.load(std::memory_order_acquire)->locked.store(false, std::memory_order_release);
    }
};
```

&emsp;&emsp;MCS 锁和 CLH 锁都是公平队列锁，MCS 锁在释放锁时效率更高，因为直接操作后继节点，但代码稍复杂；而 CLH 锁代码更简单，但释放锁时效率稍逊。选择哪种锁取决于具体应用场景，性能要求高则选 MCS，追求简单则选 CLH。它们都解决了传统锁的公平性问题，并具有良好的可扩展性。MCS更适合多核处理器和NUMA架构，因为它可以更好地利用缓存和内存局部性。

#### 2.4.4 时限队列锁
&emsp;&emsp; 时限队列锁是一种基于队列的锁实现，它允许线程在一定时间内获取锁，如果超过时限仍未获取到锁，则放弃获取。它的实现如下所示：
```cpp
class TimedMCSLock {
private:
    struct QNode {
        std::atomic<QNode*> next;
        std::atomic<bool> locked;

        QNode() : next(nullptr), locked(false) {}
    };

    std::atomic<QNode*> tail;
    thread_local QNode my_node;

public:
    TimedMCSLock() : tail(nullptr) {}

    bool try_lock_for(std::chrono::milliseconds timeout) {
        QNode* old_tail = tail.exchange(&my_node, std::memory_order_acquire);
        if (old_tail == nullptr) {
            // 锁当前空闲，直接获取
            return true;
        }

        my_node.locked.store(true, std::memory_order_release);
        old_tail->next.store(&my_node, std::memory_order_release);

        auto start_time = std::chrono::steady_clock::now();
        while (my_node.locked.load(std::memory_order_acquire)) {
            auto now = std::chrono::steady_clock::now();
            auto elapsed = std::chrono::duration_cast<std::chrono::milliseconds>(now - start_time);
            if (elapsed >= timeout) {
                // 超时，尝试从队列中移除
                if (tail.compare_exchange_strong(&my_node, nullptr)) {
                    // 成功移除，返回 false
                    return false;
                } else {
                    // 未能移除，说明已经有其他线程排在后面
                    // 需要等待锁，直到获取或被其他线程唤醒
                    // 这里可以添加一些额外的处理逻辑，例如检查后继节点是否已经释放锁
                    // 为了简化示例，这里直接继续等待
                }
            }
            std::this_thread::yield();
        }

        // 成功获取锁
        return true;
    }

    void lock() {
        QNode* old_tail = tail.exchange(&my_node, std::memory_order_acquire);
        if (old_tail != nullptr) {
            my_node.locked.store(true, std::memory_order_release);
            old_tail->next.store(&my_node, std::memory_order_release);
            while (my_node.locked.load(std::memory_order_acquire)) {
                std::this_thread::yield(); // 让出CPU
            }
        }
    }

    void unlock() {
        if (my_node.next.load(std::memory_order_acquire) == nullptr) {
            QNode* expected = &my_node;
            if (tail.compare_exchange_strong(expected, nullptr, std::memory_order_release, std::memory_order_relaxed)) {
                return;
            }
            while (my_node.next.load(std::memory_order_acquire) == nullptr) {
                std::this_thread::yield();
            }
        }
        my_node.next.load(std::memory_order_acquire)->locked.store(false, std::memory_order_release);
    }
};
```

&emsp;&emsp;时限队列锁是在队列锁的基础上增加了超时机制，允许线程在等待锁时设置一个最大等待时间，超时后放弃等待，避免永久阻塞。相比于普通自旋锁，时限队列锁保证了公平性，避免饥饿；相比于普通队列锁，时限队列锁增加了容错性，防止因死锁等原因造成的无限期等待；但相比于无超时机制的锁，实现更复杂，且超时处理可能引入额外的竞争。

### 2.5 复合锁
#### 2.5.1 复合锁
&emsp;&emsp;复合锁（Composite Lock）是指将多种锁机制结合在一起，以利用各自的优点，从而在不同场景下实现更好的性能和灵活性。所以实际上的复合锁的实现方案众多，根据具体的场景不同而不同。


### 2.6 层次锁
&emsp;&emsp;层次锁是一种通过构建多层锁结构，由粗到细逐层尝试获取，并结合退避策略来减少锁竞争，优化NUMA架构下并发性能的锁机制。

#### 2.6.1 层次后退锁
&emsp;&emsp;层次后退锁（Hierarchical Backoff Lock）是一种结合了层次锁和退避策略的锁，旨在优化在多处理器系统中的性能，尤其是在 NUMA（Non-Uniform Memory Access）架构下。 它的核心思想是，将锁的获取过程分为多个层次，每个层次对应不同的锁粒度和竞争范围，在每个层次上，如果获取锁失败，则采用退避策略，例如指数退避，以减少锁冲突。
```cpp
class HierarchicalBackoffLock {
private:
    // 假设 NUMA 节点数量已知
    static const int NUM_NODES = 4;

    // 线程本地自旋锁
    std::atomic_flag thread_local_spin_lock = ATOMIC_FLAG_INIT;
    int max_thread_spin = 100;

    // 节点级互斥锁
    std::vector<std::mutex> node_mutexes;

    // 全局互斥锁
    std::mutex global_mutex;

    // 退避参数
    int min_backoff = 10; // 微秒
    int max_backoff = 100; // 微秒
    std::random_device rd;
    std::mt19937 gen;
    std::uniform_int_distribution<> distrib;

    // 获取当前线程所属的 NUMA 节点 (简化实现)
    int get_current_node() {
        // 实际实现可能需要使用特定于操作系统的 API
        // 这里简单地使用线程 ID 模 NUM_NODES
        std::hash<std::thread::id> hasher;
        return hasher(std::this_thread::get_id()) % NUM_NODES;
    }

public:
    HierarchicalBackoffLock() : node_mutexes(NUM_NODES), gen(rd()), distrib(min_backoff, max_backoff) {}

    void lock() {
        int node_id = get_current_node();
        int thread_spin_count = 0;
        int backoff_time = min_backoff;

        // 1. 尝试获取线程本地自旋锁
        while (thread_local_spin_lock.test_and_set(std::memory_order_acquire)) {
            if (thread_spin_count < max_thread_spin) {
                thread_spin_count++;
                std::this_thread::yield();
            } else {
                break; // 自旋次数达到上限，尝试节点锁
            }
        }

        if (!thread_local_spin_lock.test(std::memory_order_acquire)) {
            // 成功获取线程本地锁
            return;
        }

        // 2. 尝试获取节点级互斥锁
        if (node_mutexes[node_id].try_lock()) {
            // 成功获取节点锁
            return;
        } else {
            // 获取节点锁失败，退避重试
            int backoff_count = 0;
            while (backoff_count < 3) { // 重试次数
                int delay = distrib(gen);
                std::this_thread::sleep_for(std::chrono::microseconds(delay));
                if (node_mutexes[node_id].try_lock()) {
                    // 成功获取节点锁
                    return;
                }
                backoff_count++;
            }
        }

        // 3. 尝试获取全局互斥锁
        global_mutex.lock(); // 阻塞等待
    }

    void unlock() {
        int node_id = get_current_node();

        // 释放锁的顺序与获取锁的顺序相反
        if (global_mutex.try_lock()) {
            // 如果持有全局锁，则释放
            global_mutex.unlock();
        } else if (node_mutexes[node_id].try_lock()) {
            // 如果持有节点锁，则释放
            node_mutexes[node_id].unlock();
        } else if (thread_local_spin_lock.test(std::memory_order_acquire)) {
            // 如果持有线程本地锁，则释放
            thread_local_spin_lock.clear(std::memory_order_release);
        }
    }
};
```
#### 2.6.2 层次 CLH 队列锁
&emsp;&emsp;层次 CLH 队列锁的基本思想是在 NUMA (Non-Uniform Memory Access) 架构下，构建一个层次化的 CLH 队列锁结构，使得线程尽可能在本地 NUMA 节点上排队等待，减少跨节点访问，从而提高性能，是一种结合了 CLH 队列锁的公平性和层次锁的 NUMA 感知特性的锁。通过维护多个 CLH 队列，每个队列对应一个 NUMA 节点，线程在本地节点上排队，当本地队列为空时，尝试在全局队列上排队。这种分层设计可以减少跨节点访问，提高性能。
```cpp
// QNode 结构体
struct QNode {
    std::atomic<bool> locked;
    QNode* next;

    QNode() : locked(true), next(nullptr) {}
};

class HierarchicalCLHLock {
private:
    // NUMA 节点数量
    static const int NUM_NODES = 4;

    // 每个 NUMA 节点的 CLH 队列尾部
    std::vector<std::atomic<QNode*>> node_tails;

    // 全局 CLH 队列尾部
    std::atomic<QNode*> global_tail;

    // 线程本地 QNode
    thread_local QNode my_node;

    // 获取当前线程所属的 NUMA 节点 (简化实现)
    int get_current_node() {
        // 实际实现可能需要使用特定于操作系统的 API
        // 这里简单地使用线程 ID 模 NUM_NODES
        std::hash<std::thread::id> hasher;
        return hasher(std::this_thread::get_id()) % NUM_NODES;
    }

public:
    HierarchicalCLHLock() : node_tails(NUM_NODES), global_tail(nullptr) {}

    void lock() {
        int node_id = get_current_node();

        // 1. 加入本地 NUMA 节点的 CLH 队列
        QNode* pred = node_tails[node_id].exchange(&my_node, std::memory_order_acquire);

        // 2. 如果本地队列为空，则加入全局队列 (可选)
        if (pred == nullptr) {
            // 尝试加入全局队列
            QNode* global_pred = global_tail.exchange(&my_node, std::memory_order_acquire);
            if (global_pred != nullptr) {
                pred = global_pred; // 使用全局队列的前驱节点
            }
        }

        // 3. 自旋等待前驱节点释放锁
        while (pred != nullptr && pred->locked.load(std::memory_order_acquire)) {
            // 自旋等待
        }
    }

    void unlock() {
        // 1. 释放锁，通知后继节点
        my_node.locked.store(false, std::memory_order_release);
    }
};
```
